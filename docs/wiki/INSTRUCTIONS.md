# 범위

**부팅(Booting) 앱에 관한 모든 것** — 제품 규칙, 왜 그렇게 정했는지, 코드가 어디에 있는지, 무엇이 아직 안 정해졌는지.

소스로 삼는 것:

1. `prd.md` 와 `docs/features/*` (기획 정본)
2. git 커밋 이력 — 이 저장소의 커밋 본문은 설계 문서 수준이라 가장 밀도 높은 소스다
3. Claude Code 세션 기록 — 결정이 **왜** 뒤집혔는지, 사용자가 무엇을 원했는지는 커밋보다 여기에 있다
4. `docs/progress/*` — 파이프라인 진행 기록

다루지 않는 것: shippen 템플릿 자체의 개발 이력 (부팅과 무관), 개인 계정 정보, 비밀값.

# 우선순위

1. **제품 규칙이 정확할 것** — "매칭 성공" 을 언제 쓰는가, 누구에게 무엇이 공개되는가 같은 규칙은 틀리면 안 된다
2. 결정의 **이유**가 남을 것 — 같은 논쟁을 두 번 하지 않도록
3. 다음 세션의 에이전트가 **30초 안에 현재 상태**를 잡을 것 (`index.md` → `open-questions.md`)
