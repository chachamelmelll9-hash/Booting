# 별명과 실명

## 규칙

- `parent_profiles.display_name` = **실명**. 입력은 받되(확인용) 어떤 공개 DTO 에도 실리지 않는다. 화면 안내: "확인용입니다. 다른 분에게는 공개되지 않습니다".
- `parent_profiles.nickname` = **공개 이름**. 2~12자 CHECK, 필수. `DiscoveryItemDto.nickname` 등 모든 공개 응답이 이걸 쓴다. 별명이 없는 옛 행만 `maskName`(`김OO`) 폴백.
- 알림·시스템 메시지도 별명으로 부른다: "{별명} 님과 대화가 연결되었습니다", "{내 부모님 별명} 님의 자녀가 프로필을 공유했습니다."
- 별명은 **조회 시점에 푼다** — payload 에 박으면 상대가 별명을 바꿔도 옛 이름이 남는다 (`2ced22e`).

## 왜 마스킹을 버렸나

PRD 7장은 `김OO` 마스킹이었다. 시드 23명이 전부 `김OO`·`이OO` 로 보이자 소유자가 "이름을 성ㅇㅇ보다는 실제이름받고 닉네임 사용하게 하는것어떄" (09-01). "`김OO` 는 이름이 아니라 자리표시자였다. 23명이 전부 비슷해 보이고 대화에서 상대를 부를 방법도 없었다." (`7b5c76b`)
프라이버시 보장은 바뀌지 않았다 — 실명은 여전히 서버 밖으로 나가지 않는다.

## 실명이 새는 경우

별명 칸이 공개되는 자리라는 걸 모른 채 실명을 적는 실수가 흔하다. 그래서:
- 별명이 실명을 포함하거나 실명이 별명을 포함하면(`nicknameLeaksRealName`, 공백 제거·소문자·2자 이상) 화면에 경고를 띄우고 저장 시 한 번 확인받는다.
- **서버는 막지 않는다.** 밝힐지 말지는 본인 선택이고 서비스가 대신 금지할 성질이 아니다 (`7b5c76b`).

## 좋은 별명

시드에서 배운 것 (`56dcb48`): "산책하는 아버지" 같은 설명형은 카드에서 두 줄로 밀리고 서로 비슷해져 결국 `김OO` 신세가 된다. **3~6자에 숫자를 섞는다** — `40년이발사` `30년수학쌤` `마라톤10년` `한강라이더` `텃밭지기`. 입력 helper 가 이 톤을 예시로 보여주고 placeholder 는 "짧을수록 잘 기억됩니다".
