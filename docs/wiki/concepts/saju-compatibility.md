# 사주 궁합

정본 스펙: [`docs/features/saju-compatibility.md`](../../features/saju-compatibility.md) (2026-09-10, 가장 최신 기획 문서). 여기는 그 요약 + 결정 맥락.

## 한 문장

부팅에서 궁합은 **필터가 아니라 순서**고, **문장이 아니라 숫자**고, **생년월일을 밖으로 내보내지 않는 계산**이다.

## 입력 — 생년월일 바로 아래

```
생년월일 [필수]  [ 1969-01-11 ]
┌ 이 날짜로 사주를 세웁니다. 사주를 기반으로 프로필을 추천해드리고 상대 부모님과의 궁합 점수를 보여드립니다. ┐
양력 · 음력 [필수]  (양력)(음력)      태어난 시간  [ 07:30 ] (모름)
```
- 사주용 날짜 칸을 따로 두지 않는다 — 두 값이 어긋나면 어느 쪽으로 세웠는지 설명할 수 없다.
- '입력 안 함' 도 '공개 여부' 도 없다. **모든 프로필에 사주가 있다**: 생년월일이 필수고 나머지는 기본값(양력/시각 모름 → 세 기둥)이 있다. `saju_infos` 는 보정값일 뿐 — 행이 없으면 `SajuService.pillarsFor` 가 `parent_profiles.birth_date` 로 폴백 (`0bf9813`).
- 시각은 숫자만 눌러도 된다(`0730` → `07:30`). 사주는 프로필을 저장할 때마다 함께 보낸다.

## 계산 — `apps/server/src/saju/lib/`

| 파일 | 역할 |
|---|---|
| `ganji.ts` | 천간 10·지지 12·오행, 합·충·삼합·방합·원진 판정. **인덱스만** — 한글 없음 |
| `solar-terms.ts` | Meeus 저정밀 태양 황경 → 절기 시각, 율리우스일수 |
| `pillars.ts` | 연주(입춘 315°), 월주(12절 30° 간격·오호둔), 일주(JDN 60갑자 `(jdn+9)%10 / (jdn+1)%12` — `korean-lunar-calendar.getKoreanGapja()` 와 9일자 대조), 시주(오서둔, **23시 이후 다음 날 자시**) |
| `compatibility.ts` | 점수·근거 코드·confidence |

- 음력 → `korean-lunar-calendar@0.4.0` (한국천문연구원 기준 1391~2050). 유일한 신규 의존성.
- **1954-03-21 ~ 1961-08-09** (및 1908-04-01~1911-12-31) 는 UTC+8:30 표준시 → 30분 보정. 지금 만 65~72세가 이 구간이라 안 하면 시주가 통째로 어긋난다.
- 경도 보정(서울 −32분)은 **하지 않는다** — KASI 만세력이 표준시를 쓰고, 유파에 따라 갈리는 값을 서버가 임의로 고를 이유가 없다.
- 절기 오차 ±0.01° ≈ **±15분**. 절입 15분 안쪽 출생은 만세력과 월주가 갈릴 수 있다(<0.1%). 시각 '모름' 이 더 많다는 점이 이 정밀도를 택한 근거다.

### 점수

기본 20 + 항목 합을 항목 만점·최저점 기준으로 **30~99** 로 정규화 (`Math.round(30 + 69 * (raw - low) / (high - low))`).

| 항목 | 배점 |
|---|---|
| 일간(부부의 중심) | 천간합 25 / 상생 18 / 비화 12 / 상극 7 / 충 4 |
| 일지(배우자궁) | 육합 22 / 삼합 20 / 방합 14 / 동일 10 / 무관 6 / 충 −8 |
| 연지(띠) | 삼합·육합 12 / 무관 5 / 충 −6 / 원진 −8 |
| 월지 | 합 8 / 무관 3 / 충 −5 |
| 오행 균형(합산) | 0~18 |
| 음양 조화(합산) | 0~8 |
| 시지(양쪽 다 알 때만) | 합 6 / 무관 2 / 충 −4 |

정규화라 **시주가 빠져도 점수가 깎이지 않는다** — 만점·최저점이 함께 줄어든다. `confidence: medium` 으로 그 사실만 남긴다(화면엔 안 나온다).
실측 분포(50세 이상 2,016쌍): 최소 43 / Q1 64 / 중앙 69 / Q3 74 / 최대 92, 평균 69.0. `distribution.spec.ts` 가 뭉침·극단 비율을 지킨다. 테스트 25건.

## 노출 — 두 값만, 모든 화면 같은 글자

| 자리 | 표기 |
|---|---|
| 카드(뒤집은 뒤) | `아침걷기 · 53세` / `병인일주` / `궁합 74점` |
| 펼친 카드 · 상세 · 매칭 목록 · 매칭 성공 · 대화방 헤더 · **부모님 웹** | `병인일주 · 궁합 74점` 한 줄, 민트(`#0D9488`, 사진 위는 `#CCFBF1`) |
| 추천 순서 | 궁합 높은 순 — 화면에 조작 장치 없음 |

- **일주는 그 프로필 본인의 것**(우리 부모님 것이 아니다). 60일 주기라 나이를 알아도 후보 날짜가 여럿 남아 그대로 나간다.
- **뺀 것**: 등급 문구(`천생연분`/`무난한 궁합`), 근거 풀이, 두 사람의 네 기둥, "재미로 보는 참고 정보" 고지. "숫자는 참고로 읽히지만 문장은 결론으로 읽힌다. 점수가 낮게 나온 상대도 누군가의 부모님이고 그 문장을 자녀가 본다." (`4d30c04`)
- 서버는 코드(인덱스·점수·reason 코드)만 내리고 한글은 `apps/mobile/src/shared/config/saju.ts` 한 곳 — 단, **부모님 웹은 서버 렌더**라 `parent-view.controller.ts` 에 천간·지지 표가 한 벌 더 있다. 두 표의 글자가 같아야 한다.
- 부모님 웹의 궁합은 '부모님 본인과 상대' 값 = 자녀가 보는 숫자와 같다.

## 프라이버시

- **원본 생년월일·출생시각은 어느 응답에도 없다.** `PublicProfileDto.saju`·`sajuPillars` 제거. 본인 조회(`GET /parent-profile`)에는 온다.
- **네 기둥도 없다** — 기둥 넷이면 60갑자 안에서 생년월일이 거의 특정된다.
- `saju_infos.is_public` 은 **항상 false**. 이 컬럼이 실제로 여는 문은 RLS 정책 `saju_public_read` 다 — true 면 우리 API 가 안 내보내도 인증된 아무나 PostgREST 로 그 행을 직접 읽는다. 시드 데이터도 전부 false 로 내렸다 (`fa732ae`).
- 외부 API 를 쓰지 않는 이유도 여기 있다 — 부모님 생년월일·시각을 외부 업체에 보내면 개인정보 제3자 제공이라 별도 동의·처리방침 항목이 필요하다 (09-09 세션). 계산은 결정론적 천문 계산이라 매번 같은 답이 나온다.

## 데이터

새 컬럼 없음. 사주팔자는 저장하지 않고 매번 계산. `discovery_filters.sort/min_compatibility` 는 넣었다가 되돌리는 마이그레이션으로 지웠다 (`20260909120000` → `20260909170000`).
