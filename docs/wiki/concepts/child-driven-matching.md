# 자녀 주도형 매칭

> "우리 부모님의 새로운 인연을, 가장 잘 아는 자녀가 소개합니다." — PRD 1.3

## 누가 무엇을 하나

| 역할 | 어디서 | 무엇 |
|---|---|---|
| **자녀** (앱 사용자, `auth.users`) | 모바일 앱 | 계정 확인 → 부모님 동의 받기 → 프로필 등록 → 추천 보기 → 관심 보내기 → 상대 자녀와 대화 → **부모님께 카톡으로 프로필 전달** |
| **부모님** (계정 없음, `parent_profiles`) | 카카오톡 → 서버가 그린 웹 페이지 | 등록 동의(링크) · 받은 프로필 보기 · **"대화해보고 싶어요" / "아니요"** |
| **서버** | NestJS | 추천·제외·궁합 계산, 상호 하트 판정, **매칭 판정**(양쪽 부모님), 연락처 공개, 부모님 웹 렌더 |

부모님은 **앱을 설치하지 않는다.** 60~70대에게 스토어 설치와 코드 입력을 요구하면 마지막 한 걸음에서 대부분이 멈춘다 — [결정 2026-09-08](../decisions/2026-09-08-parent-web-not-app.md). PRD 의 부모님 접점도 원래 '동의' 하나였다.

## 일반 매칭 앱과 다른 점 (core-idea.md)

| | 일반 매칭 앱 | 부팅 |
|---|---|---|
| 앱을 쓰는 사람 | 본인 | **자녀** |
| 등록 대상 | 본인 | **사별 또는 이혼**한 부모님만 (별거 제외), 만 50세 이상 |
| 상호 호감 | "매칭 성공" | **"대화 연결"** — 성공이 아니다 |
| 최종 성공 | 매칭 시점 | **양쪽 부모님이 각자 '만나보고 싶다'고 한 시점** (원래 PRD 는 '실제로 만나 양측 확인'이었다 — [결정](../decisions/2026-09-01-matching-at-parent-intent.md)) |
| 결정권 | 본인 | 프로필 공개·만남 모두 **부모님** |

## 한 사람이 겪는 전체 흐름 (2026-09-11 기준)

```
자녀 가입 → 계정 확인(카카오 연결) → 부모님 동의 링크 카톡 발송 → 부모님이 [동의합니다]
→ 프로필 6섹션 작성(사진 3~5장, 생년월일 + 양음력·시각) → 미리보기 → 공개
→ 홈 '오늘의 추천' 원석 카드 6장(궁합 높은 순) → 카드 뒤집기 → 관심(+인사말)
→ 상대 자녀도 관심 = 대화 연결 (인사말이 첫 메시지) → 자녀끼리 대화
→ 매칭 탭 카드의 [부모님께 공유] → 카톡 카드 → 카카오 서버 콜백 → '공유 완료' + 상대 대화방에 한 줄
→ 부모님이 카톡 카드 [프로필 보기] → 웹 /p/:token → [대화해보고 싶어요]
→ 상대 부모님도 누르면 → 매칭 성공 → 양쪽 부모님 웹에 서로의 연락처(전체 번호)
```

## North Star

단순 하트 수가 아니라 **양측 부모님이 실제 만남을 완료한 건수** (PRD 19). 앱이 재는 마지막 지표는 '연락처가 열린 건수'다 — 만남 자체는 앱 밖에서 일어난다.
