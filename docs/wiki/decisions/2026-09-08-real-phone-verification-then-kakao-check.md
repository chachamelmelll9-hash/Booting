# 본인인증 → 계정 확인

## 배경
"이제 진짜 앱 배포할거야"(09-07). 인증은 09-01 스텁(숫자면 통과) 그대로였다 — 화면은 "자녀분 본인 확인" 이라 말하는데 아무도 확인하지 않았다. 소유자(09-08): "일단 본인인증 시작해줘 부모암ㄹ호는 생각좀해볼게" → 마이그레이션이 유니크 인덱스에서 실패 → "근데 초기화하면 화면테스팅을못하잔아" / "이건 배포직전에 하는게 낫진않아?" → "흠 혹시 카카오로그인만 가능하게하면 문자인증 이거 생략해도되나" → "사업자는 없고....... 아모르겟어 그냥 본인확인할수잇게해줘 카카오로그인으로".

## 결정
1. **문자 인증 실물화** (`3995f52`): 6자리 `randomInt`, 서버 비밀을 섞은 해시로만 저장, 3분/5회/60초, 실패 이유 뭉뚱그림, 통과 시 폐기, 번호당 계정 1개, 실제 번호 형식. `SmsService` 는 키가 없으면 **개발: 로그 / 운영: 던진다**.
2. 유니크 인덱스·스텁 인증 비우기는 **배포 직전 SQL** 로 (`e944130`) — 지금 하면 테스트 계정이 등록 첫 단계로 돌아간다.
3. **카카오 연결 = 확인** (`46a5735`): `canCreateProfile = phoneVerified || kakaoLinked`. 근거는 `social_identities` PK — 카카오 계정 하나는 부팅 계정 하나에만. 남은 몫이 정확히 "한 사람이 계정을 여러 개 만들지 못하게" 이다(진짜 자녀인가는 부모님 동의가 맡는다).
4. 문구: "계정을 한 번 확인합니다 / 한 분이 계정을 여러 개 만들어 등록하시는 것을 막기 위한 절차입니다" — 실명·전화번호를 못 받는 절차가 "본인 확인" 이라 말하면 안 된다. 헤더도 (`703383a`).
5. 문자 사업자가 없으면 휴대폰 항목을 **감춘다** (`45900cf`, `phoneAvailable`). 사업자가 붙으면 앱 수정 없이 살아난다.

## 버린 대안
- 스텁 유지 — 아무도 확인하지 않는 채로 서비스가 열린다. 스토어·처리방침에 '하지 않는 일' 을 한다고 적는 문제.
- 문자 경로 삭제 — 지우지 않는다. 사업자 계약이 붙는 순간 한 줄도 안 고치고 되살아나야 한다.
