# 부모님 화면 (앱) — 대체됨

## 배경
"부모님이 자녀에게 프로필을 받고도 볼 곳이 없었다. 자녀가 부모님을 대신해 '부모님 의사 확인' 을 눌러 주는 구조라, 그 결정이 누구 것인지 아무도 몰랐다." 소유자(09-03): "공유받은 부모님 입장에서 화면이랑 UI도 만들어야 할것같아 회원가입 없이 자녀코드만 넣으면 로그인 되고 … 대화해보고 싶어요(양쪽이 서로 선택시 축하합니다 ~님과 마음이 통했습니다! 팝업 … 연락처 공개) / 다른 프로필 볼래요".

## 결정 (당시)
- **코드 로그인** — 회원가입도 비밀번호도 없다. 부모님 프로필당 코드 하나, 만료 없음, 헷갈리는 글자(0/O/1/I/L) 제외 6자리 → [09-04 숫자 8자리](2026-09-04-numeric-8-digit-parent-code.md).
- 받은 프로필 스택, 안 본 카드 초록 테두리, `대화해보고 싶어요` / `다른 프로필 볼래요`(되돌릴 수 없어 한 번 더 확인 → 인연 종료).
- **부모님 세션은 자녀 세션과 저장 위치부터 분리**(`parent-session`), 서버 `ParentGuard` + `/api/parent/*` 표면 분리 — 부모님이 자녀 화면(추천·대화)을 보는 것은 이 서비스가 절대 하면 안 되는 일.
- 자녀 화면의 '부모님 의사 확인' 버튼·`POST /parent-intent` 삭제. 공유하면 인연이 `parent_intent` 로.
- 부모님 연락처를 동의 방법과 무관하게 **필수**로 — 대면 동의 부모님은 매칭돼도 열어드릴 번호가 없었다(E2E 실측).
- 화면 치수(코드 40sp, 소개 30px 행간)는 60~70대 기준. 전화 걸기 버튼은 뺌, 상세는 자녀가 보는 전체 프로필과 같은 내용 (`aa4e941` — 서로 다른 내용을 보면 두 분이 다른 사람을 두고 이야기하게 된다).

## 왜 대체됐나
부모님께 **앱 설치와 8자리 코드**를 요구하는 것은 PRD 에 없던 요구였다(PRD 의 부모님 접점은 동의 하나). 60~70대에게 스토어 설치와 코드 입력을 요구하면 마지막 한 걸음에서 대부분이 멈춘다. 소유자(09-07): "부모님은 앱 다운안받아도되는거야? … 나는 그거 기획한적이없는데" → [2026-09-08 웹](2026-09-08-parent-web-not-app.md).

## 남은 것
서버 `/api/parent/*`, `parent_profiles.access_code`, `parent_sessions` — 앱 화면만 지웠다(`eac0e7c`). 판정 함수 `recordInterest` 는 앱/웹 공용으로 살아 있다. `withKakaoLinkScheme.js` 인텐트 필터는 미사용.
