# 증명서 재도입 — 올리면 통과

## 배경
소유자(09-18): "가족관계증명서 확인 뺐었는데 다시 추가해야 할 것 같아. 자식이 아니라 남이 올리면 어떡해!" 논의 순서: 동의를 부모님 폰에 묶기 → "부모님인지 확인이 안 되잖아" → 증명서 + 운영자 수동 심사 → "아무한테나 카톡 보내면?" → 사업자 없이는 어떤 서류도 사칭을 완전히 못 막는다는 점을 확인 → "심사 없이 계정 만들 수 있게, AI 자동 심사로" → "API 키까진 안 쓰고 싶고 올리기만 하면 패스, 사람이 나중에 적발하면 바로 제한".

## 결정
- 프로필 작성 3단계에 **가족관계 확인(필수)** 섹션: 자녀 본인 성함 + 증명서 사진(비공개 버킷 `family-docs/{userId}/…`).
- `POST /me/verification/family-doc` — 접수 즉시 `family_doc_status = approved`, 사진은 **버킷에 보관**(`family_doc_path`). 신고·의심 시 운영자가 열어 보고 사실과 다르면 `rejected` + 프로필 `hidden` 으로 제한한다.
- 서버에 `ANTHROPIC_API_KEY` 가 있으면 **선택적으로** Claude 가 표를 읽고(`FamilyDocReaderService`, 구조화 출력) 코드가 대조한다(`judge()`: 본인 성함 = 자녀 성함, 부/모 줄의 성함·생년월일 = 프로필). 안 맞으면 반려하고 사진을 지운다. 판정을 AI 에게 통째로 맡기지 않는 이유: 반려 사유를 사용자가 읽고 고칠 수 있어야 한다.
- 프로필 `missing` 에 `familyDoc` — 승인 전 제출 불가. **이미 published/hidden 인 프로필은 소급하지 않는다**(시연 계정 보호).
- 마이그레이션 없음 — 09-04 에 남겨 둔 `family_doc_*` 컬럼과 버킷을 그대로 쓴다.

## 버린 대안
- 부모님 폰 번호에 동의 링크 묶기 — 동의자가 폰 주인임만 증명하고, 프로필의 그 사람인지·자녀인지는 못 증명한다.
- 운영자 수동 심사 — 등록마다 사람이 봐야 해서 시연·초기 운영에서 멈춘다.
- AI 대조를 필수로 — 소유자가 API 키를 쓰고 싶지 않다고 했다. 선택 기능으로 남긴다.

## 근거
사업자·본인인증(PASS) 없이는 증명서도 동의도 우회된다. 그렇다고 모두를 심사에 세우면 아무도 통과하지 못한다. "제출은 쉽게, 거짓이면 책임" 이 지금 조건에서 정직한 선이고, 보관된 증명서가 그 책임을 물을 근거가 된다. 09-04 의 "증명서는 모든 자녀를 주민센터로 보낸다" 는 여전히 맞다 — 그 비용을 소유자가 다시 받아들인 것이다.

## 이후
- PASS 본인인증을 동의 화면에 붙이는 것이 진짜 해법 — 사업자 등록 후.
- 증명서 보관은 개인정보(주민번호 포함)라 스토어 데이터 안전 선언에 "신분 서류 수집" 이 추가돼야 한다. 발급 시 뒷자리 가림 안내는 아직 없다.
- 운영자 제한 조치 화면은 없다 — 지금은 Supabase 대시보드에서 직접.
