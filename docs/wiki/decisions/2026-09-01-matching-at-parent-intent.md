# 매칭 지점

## 배경
원래 동선: 상호 하트 → 대화 → 부모님 의사 → 일정 제안 → 수락 → 양측 만남 확인 → 매칭. 자녀가 앱에서 눌러야 할 단계가 6개였다. 소유자(09-01): "대화 중 만남예정 매칭성공 종료 이건 어떻게 결정되는거야?" → "부모님이 만나보고 싶다고 하세요 누르면 매칭성공 으로 끝내자".

## 결정
- **양쪽 부모님이 '만나보고 싶다' 면 그 자리에서 `matched`.** 한쪽만이면 `parent_intent` 에 머문다 ([두 사람 규칙](../concepts/two-person-rule.md)).
- `matched` 는 종착점 — 이후 일정 API 를 부르든 되돌리지 않는다. 한 번 본 '매칭 성공' 이 취소된 것처럼 보이면 안 된다. 실패를 조용히 삼키던 `setStatus` 도 로그로 드러냄.
- 일정·미동행·만남 확인·사후 응답 **화면은 동선에서 뺀다**. API 와 라우트는 남긴다(사후 응답이 완료된 만남을 전제, 나중에 꺼낼 여지). 시나리오 Step 18/19 는 'API 전용'.
- 매칭 탭 칩 5 → **전체 / 매칭** 2.
- 시드 `--partner-intent` — 상대측 의사를 미리 채워 데모가 한 번 누르면 매칭되게 (규칙을 느슨하게 하지 않고 데모만 굴러가게).

## 근거
약속 시간·장소는 채팅으로 정하는 편이 자연스럽다. 앱이 대신 관리하면 이미 매칭된 사람에게 할 일이 남은 것처럼 보인다.
