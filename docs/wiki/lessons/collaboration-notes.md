# 소유자와 일하는 방식

소유자 = 개발자 본인이자 이 서비스의 기획자. **개인 개발자(사업자등록 없음)**, 본인 폰은 아이폰, 여러 환경에서 작업한다(09-06 커밋은 이 머신 밖). 이 페이지는 다음 세션의 에이전트가 같은 실수를 반복하지 않기 위한 관찰 기록이다.

## 확인해 주길 바라는 것

- **에뮬레이터에서 실제로 보인 것**을 원한다. 요청 대부분이 스크린샷을 보고 나온다. 구현했다는 말보다 덤프·스크린샷 결과.
- 같은 값이 여러 화면에 나오면 **전부** 확인한다. 카드·펼친 카드·상세 중 하나를 빠뜨리자 "잠만 나 허점 발견햇어 … 똑바로 안할래??" / 부모님 화면을 빠뜨리자 "매칭된 프로필에서는 사주정보가 하나도 안뜨잖아~~~".
- 버그가 아닌 것은 버그가 아니라고 말하면 받아들인다 ("조건에 맞는분이 없다" → 필터 vs 시드 나이). 원인이 인프라(서버 죽음·터널 주소)면 그것부터.
- 문서 동기화를 요구한다: "지금까지 수정사항 관련문서에도 다 반영해주고".

## 표현 읽기

| 표현 | 뜻 |
|---|---|
| "에뮬레이터 (좀) 내려줘", "아래로 내려조" | **창을 아래로 옮겨라** (위가 잘렸다). 종료가 아니다 — 09-09 에 종료해 버려 "아니 없애라는게 아니라 아래로 내려달라고" |
| "띄워줘", "켜줘" | 실행해서 보여 달라 |
| "~어떄", "~하는거어떄", "가능?" | 제안. 동의하면 바로 진행해도 된다 |
| "B로 가줘", "1번으로" | 제시한 선택지 중 고름 |
| "아니 …" 로 시작 | 앞 답이 틀렸다. 정정하고 짧게 |
| "…이해햇지?", "…맞지?" | 요약해서 확인하되 길게 되묻지 않는다 |
| 느낌표·물결·오타 | 급함/답답함의 강도. 문장 뜻 자체는 그대로 |
| "사장님" 이라 부르면 | 싫어한다 — "사장님이 앱개발자인 나야?" |

## 결정 권한

소유자가 정하는 것 — 비용이 드는 것(도메인, 클라우드, 안심번호 → 유료라 거절), 법·계정이 필요한 것(사업자, 카카오 비즈니스 앱, 문자 사업자), 제품 규칙(문구, 노출 범위, 무엇을 뺄지). **선택지와 비용을 표로 주고 기다린다.** 큰 갈림길(사주 노출 범위·계산 깊이)에는 AskUserQuestion 이 잘 먹었고, 작은 것에 물으면 "그냥 해" 로 반려된다.

에이전트가 정해도 되는 것 — 구현 방식, 파일 배치, 테스트, 문구의 톤(단 결론형 문장은 피한다 — 궁합 등급 문구 제거가 그 예).

## 속도와 형식

- 답은 짧게, 결론 먼저. 표는 좋아한다. 긴 설명은 읽히지 않는다.
- 분류기가 막는 명령은 **`! 명령`** 한 줄로 넘기면 바로 실행해 준다. 두 줄을 한 번에 주면 `&` 로 붙여 넣어 깨진다 — 한 줄씩.
- 메모장 편집 지시는 "본문 클릭 → Ctrl+End → Enter → 붙여넣기 → Ctrl+S" 처럼 순서로. 파일 끝의 주석 줄(`# REDDIT_…`)에 붙여 넣거나 `#` 을 남기는 일이 두 번 있었다.
- 커밋·푸시는 요청 없이도 세션 완료 규칙대로 한다. 되돌릴 수 없는 것(DB 쓰기·설치·삭제)은 확인.

## 정정은 짧게

이 세션들에서 에이전트가 정정한 것: fetch 전 판단, "12개월 무료", Elastic IP 무료, "비공식 브릿지", OpenCode 무료 티어 추천, "사장님". 한 문장으로 정정하고 다음으로 넘어갔을 때 대화가 가장 잘 흘렀다.
