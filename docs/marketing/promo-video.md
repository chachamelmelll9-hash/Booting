## 만드는 법

```powershell
cd scripts\promo-video

# 1) 앱 화면 (에뮬레이터가 로그인된 상태여야 한다). -Dump 로 탭 좌표를 얻는다
.\shot.ps1 -Name 01_home_gems -Tap "135,2299" -Dump

# 2) 부모님 웹은 헤드리스 Chrome 으로 길게 (스크롤 애니메이션에 쓴다)
#    주소: node ..\..\scripts\open-parent-web.mjs <connectionId> --print
.\render.ps1 -Url "http://localhost:3000/p/<token>" -Out shots\13_tall.png -W 480 -H 3000 -Scale 2.25

# 3) 폰 화면 비율(1080x2230)로 정규화
.\crop.ps1

# 4) 프레임 캡처 — 설치된 Chrome 을 puppeteer-core 로 몰아 1800장씩 (각 3~4분)
node capture.mjs --layout tall --fps 30 --dur 60 --out frames/tall
node capture.mjs --layout wide --fps 30 --dur 60 --out frames/wide

# 5) 인코딩 (각 1분)
.\encode.ps1 -Frames frames\tall -Out promo-9x16.mp4 -Audio music.mp3
.\encode.ps1 -Frames frames\wide -Out promo-16x9.mp4 -Audio music.mp3
```

자막·타이밍·움직임은 전부 `anim.html` 의 `SC` 배열 하나에 있다. 문구만 고치면 4~5단계만 다시 돌리면 된다.

### 구조

`anim.html` 은 `window.seek(t)` 하나를 노출한다 — t초 시점의 모든 요소 위치·투명도를 계산해 DOM 에 반영한다. CSS 애니메이션을 쓰지 않는 이유: 캡처가 벽시계 시간에 의존하면 프레임이 밀리거나 겹친다. `capture.mjs` 는 `seek(t)` → `screenshot()` 를 1800번 반복하므로 결과가 완전히 결정적이다.

`?layout=wide` 로 같은 타임라인을 1920×1080 레이아웃으로 렌더한다.

### 걸렸던 것

- **`adb screenrecord` 는 못 쓴다.** 에뮬레이터가 swiftshader(소프트웨어 렌더링)라 프레임이 1장만 잡힌다. 그래서 스크린샷을 찍어 브라우저에서 움직임을 만든다.
- **첫 버전은 슬라이드쇼였다.** 정지 이미지에 크로스페이드만 걸면 "사진이 뚝뚝 나온다". 폰 안에서 실제로 스크롤·전환·탭이 일어나야 앱처럼 보인다.
- **장면 전환에 빈 프레임.** 나가는 장면을 다음 장면 시작 *전에* 페이드아웃하면 이음매에서 둘 다 0이 된다. 나가는 장면은 들어오는 장면의 페이드인 *위에서* 빠져야 한다.
- **`zoompan` 의 `d` 는 입력 프레임마다 곱해진다** (구버전 파이프라인). `-loop 1 -t 6` 으로 넣으면 60초가 370초가 된다.
- **PowerShell 5.1 은 BOM 없는 UTF-8 `.ps1` 을 ANSI 로 읽는다.** 한글 주석의 깨진 바이트가 뒷줄을 삼킨다. 여기 `.ps1` 은 전부 ASCII 다.
- **`@(...)` 안에서 줄 끝 `+` 문자열 결합이 안 붙는다.** 두 개 원소로 쪼개져 뒷부분이 출력 파일명으로 해석된다(`Error opening output files`). 긴 필터 문자열은 배열 밖에서 변수로 만든다.
- `"$X:..."` 는 스코프 한정자로 읽힌다. `"$($X):..."` 로 감싼다.
