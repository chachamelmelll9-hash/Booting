# Feature: 첫 만남 & 최종 매칭 확정

## User Goal

자녀가 각자 부모님의 만남 의사를 확인하고, 양측 의사가 확인되면 매칭을 매듭짓는다.

## Summary

대화 중인 자녀가 각자 부모님께 상대를 소개하고 만남 의사를 확인한다.
**양측 부모님이 모두 '만나보고 싶다'고 하면 그 자리에서 매칭 성공이다.** 한쪽만 답한
동안에는 '부모님 의사 확인' 상태에 머문다 — 한쪽 답변으로 매칭 성공을 띄우면 상대
부모님은 아무 말도 하지 않았는데 성사된 것처럼 보인다. 이 앱에서 오해가 가장 비싼
지점이라 두 사람 규칙을 상태 하나에 그대로 박아 뒀다.

만남 이후 비공개 응답(계속 이어가고 싶어요 / 좋은 친구로 / 더 생각해볼게요 /
더 만나지 않을래요)은 상대에게 평가나 점수 형태로 공개하지 않는다.

### 앱 동선에서 뺀 것 — 일정 조율

원래는 `의사 확인 → 일정 제안 → 상대 수락 → 만남 후 양측 확인 → 매칭`까지 갔다.
자녀가 앱에서 눌러야 할 단계가 6개였는데, 정작 약속 시간·장소는 채팅으로 정하는 편이
자연스럽다. 앱이 대신 관리할 이유가 없는 일을 화면으로 만들면, 이미 매칭된 사람에게
계속 할 일이 남은 것처럼 보인다.

일정·만남 확인 **API 는 그대로 살아 있다**(`POST /connections/:id/meeting` 이하).
사후 응답이 완료된 만남을 전제로 하기 때문이고, 나중에 다시 꺼낼 여지를 남겨서다.
다만 앱 화면은 의사 확인에서 끝나고, `matched` 는 종착점이라 이 API 를 어떻게
부르더라도 상태가 되돌아가지 않는다.

## User Journey

### Step 1: 발견 — 대화 중 만남 제안 진입점

- **사용자가 보는 것**: 채팅방 상단 액션 바에 `부모님 의사 확인` 버튼. 인연 관리의 '대화 중' 항목에도 동일 CTA
- **사용자가 하는 것**: 부모님께 상대 프로필을 보여준 뒤 버튼 탭
- **시스템 피드백**: 의사 확인 시트 오픈, 상태가 '부모님 의사 확인 중'으로 전이
- **시각적 위계**: 대화 내용 → 상단 액션 바 → 상태 배지
- **States**:
  - Loading: 상태 전이 중 버튼 스피너
  - Error: "상태를 변경하지 못했어요. 다시 시도해주세요."
  - Success: 상태 배지 갱신 + 상대에게 알림

### Step 2: 입력 — 부모님 만남 의사 확인

- **사용자가 보는 것**: 시트에 3지선다 — `만나보고 싶다고 하세요` / `조금 더 생각해보신대요` / `이번엔 어렵대요`. 하단에 "부모님께 상대 프로필을 보여드리고 여쭤봐 주세요" 안내. 상대가 이미 답했으면 "상대측은 이미 답변을 보냈습니다. '만나보고 싶다'를 고르시면 매칭됩니다."
- **사용자가 하는 것**: 선택 후 제출
- **시스템 피드백**: 동의 → 상대 확인 대기. **양측 동의 시 그 자리에서 `matched`** (매칭 성공). 거절 → 확인 다이얼로그 후 인연 종료(상대에게는 사유 없이 "이번에는 인연이 닿지 않았어요"만 전달)
- **시각적 위계**: 질문 문장 → 3개 선택지(동의가 기본 강조) → 안내 문구
- **States**:
  - Loading: 제출 스피너
  - Empty(대기): "상대방의 부모님 의사를 기다리고 있어요"
  - Error: "응답을 저장하지 못했어요. 다시 시도해주세요."
  - Success: "부모님 의사를 전달했어요" 토스트

### Step 3: 입력 — 첫 만남 일정 등록

- **사용자가 보는 것**: 만남 등록 폼 — 날짜·시간 / 장소(공공장소 추천 문구 + 직접 입력) / 동행 자녀 여부(기본값 **동행함**) / 메모. 상단에 원칙 배너 "첫 만남은 자녀와 함께하는 것을 권해드려요."
- **사용자가 하는 것**: 채팅으로 조율한 내용을 입력하고 제안 → 상대가 수락/수정 제안
- **시스템 피드백**: 제안 시 상대에게 알림 + 채팅방에 일정 카드 삽입. 상대 수락 시 상태가 '만남 예정'으로 전이
- **시각적 위계**: 원칙 배너 → 날짜·시간 → 장소 → 동행 여부 → 메모
- **States**:
  - Loading: 제출 스피너
  - Empty: 일정 없음 상태에서 "아직 만남 일정이 없어요" + `일정 제안하기`
  - Error(날짜): "지난 날짜는 선택할 수 없어요"
  - Error(장소): "만남 장소를 입력해주세요"
  - Error(제출): "일정을 등록하지 못했어요. 다시 시도해주세요."
  - Success: "만남 일정을 제안했어요" + 채팅방 일정 카드

### Step 3.5: 분기 — 자녀 미동행 선택 시

- **사용자가 보는 것**: 동행 여부를 '동행하지 않음'으로 바꾸면 확인 시트 — "첫 만남은 자녀 동행을 강력히 권해드려요." + 미동행 사유 입력(필수) + 안전수칙 3항 재확인 체크박스(공공장소 / 일정 공유 / 만남 후 안부 확인)
- **사용자가 하는 것**: 사유 입력 + 체크 3개 후 `이해했고 진행할게요`
- **시스템 피드백**: 사유·확인 시각 기록, 일정 카드에 '자녀 미동행' 표기(양측 모두에게 보인다)
- **시각적 위계**: 권고 문구 → 사유 입력 → 체크박스 3개 → 진행 버튼(체크 전까지 비활성)
- **States**:
  - Error: "미동행 사유를 입력해주세요" / "안전수칙을 모두 확인해주세요"
  - Success: 시트 닫힘 + 일정 카드에 표기

### Step 4: 대기 — 만남 전 리마인드

- **사용자가 보는 것**: 인연 관리 '만남 예정' 카드에 D-day, 만남 하루 전 푸시 "내일 첫 만남이 있어요. 장소와 시간을 다시 확인해주세요."
- **시스템 피드백**: 만남 시각 경과 후 상태를 '만남 확인 대기'로 자동 전이하고 확인 요청 알림 발송
- **States**:
  - Empty: "예정된 만남이 없어요"
  - Success: D-day 카운트 표시

### Step 5: 결과 — '부모님끼리 만났어요' 양측 확인

- **사용자가 보는 것**: 만남 카드에 큰 버튼 `부모님끼리 만났어요`. 한쪽만 눌렀으면 **"상대방의 만남 확인을 기다리고 있어요"** 상태 문구
- **사용자가 하는 것**: 만남 후 버튼 탭
- **시스템 피드백**: 내 확인 기록 → 상대 미확인이면 대기 상태. 양측 확인 완료 시 **매칭 성공**으로 전환 + 축하 화면 + 알림
- **시각적 위계**: 현재 상태 문구 → 확인 버튼 → 만남 정보(일시·장소) → 안전 관련 보조 액션
- **States**:
  - Loading: 버튼 스피너
  - Empty: 해당 없음
  - Error: "확인을 저장하지 못했어요. 다시 시도해주세요."
  - Error(만남 전): "만남 예정 시각 이후에 확인할 수 있어요"
  - Success(한쪽): "확인했어요. 상대방의 만남 확인을 기다리고 있어요."
  - Success(양쪽): "매칭 성공" 축하 화면
- **재알림**: 상대 미확인 상태가 3일 지속되면 상대에게 재알림 1회

### Step 6: 후속 행동 — 만남 이후 비공개 응답

- **사용자가 보는 것**: 확인 직후 시트 — "만남은 어떠셨나요?" 4지선다(인연을 계속 이어가고 싶어요 / 좋은 친구로 지내고 싶어요 / 조금 더 생각해볼게요 / 더 만나지 않을래요) + "상대방에게 공개되지 않아요" 고지
- **사용자가 하는 것**: 하나 선택 또는 `건너뛰기`
- **시스템 피드백**: 저장만 하고 상대에게 노출하지 않는다. 서비스 개선·안전 관리 목적으로만 사용
- **시각적 위계**: 질문 → 4개 선택지 → 비공개 고지(작지만 명확히) → 건너뛰기
- **States**:
  - Error: "응답을 저장하지 못했어요."
  - Success: 시트 닫힘, 별도 축하/평가 노출 없음

### Step 7: 이탈/완료 — 매칭 이후

- **사용자가 보는 것**: 매칭 탭 '매칭' 필터 목록. 채팅방은 90일간 유지되고 남은 기간을 표시
- **시스템 피드백**: 90일 경과 시 채팅방 읽기 전용 전환 안내
- **States**:
  - Empty: "아직 최종 매칭이 없어요"
  - Success: 성공 목록 + 채팅방 잔여 기간

## Visual Hierarchy Notes

- 의사 확인 화면에서 가장 먼저 봐야 할 정보 1가지: **현재 상태 문구**("상대방의 부모님 의사를 기다리고 있어요"). 사용자가 가장 헷갈려 하는 지점이 "내가 눌렀는데 왜 아직인가"이므로 버튼보다 상태가 위다.
- 일정 화면에서 가장 먼저 봐야 할 정보 1가지: **날짜·시간**. 장소는 그다음.
- 미동행 확인 시트는 권고 문구가 가장 크고, 진행 버튼은 체크 완료 전까지 시각적으로 눌리지 않게 보인다.
- CTA 레이블: `부모님 의사 확인`, `일정 제안하기`, `부모님끼리 만났어요`, `이해했고 진행할게요`.

## Consistency Checklist

- [ ] 상태 문구가 PRD 10.3의 9개 목록과 글자 단위로 일치한다
- [ ] '매칭 성공'은 양측 확인 이후에만 어디에서도 등장한다
- [ ] 확인/제안 버튼이 채팅방·인연 관리·만남 화면에서 동일 컴포넌트다
- [ ] 안전 관련 문구(공공장소·연락처·귀가 확인)가 동일 어투로 반복된다

## Accessibility Notes

- 터치 타겟 최소 44×44px, `부모님끼리 만났어요`는 56px 높이의 주 버튼
- 상태 배지는 색 + 아이콘 + 텍스트 병행 (대기/완료를 색만으로 구분하지 않는다)
- 날짜·시간 선택은 네이티브 피커를 쓰고 직접 입력 대안을 함께 제공
- 체크박스 3개는 각각 라벨 전체가 터치 영역
- D-day는 "3일 뒤" 같은 상대 표현과 절대 일시를 함께 제공

## Technical Notes

- **Processing**: Server-side (상태 전이·양측 확인 판정·재알림 스케줄), 클라이언트는 표시와 입력만
- **Data Flow**: 의사 확인 응답 → 양측 동의 판정 → 만남(meeting) 레코드 생성 → 제안/수락 → 만남 시각 경과 → 각자 confirm 기록 → 둘 다 true면 최종 매칭 전이 → 사후 응답 비공개 저장
- **양측 확인**: 확인은 참여자별 개별 플래그로 저장하고 최종 전이는 서버에서만 판정한다 (클라이언트가 '성공'을 선언하지 않는다)
- **재알림**: 미확인 3일 경과 시 1회 (스케줄러 또는 조회 시점 지연 평가)
- **비공개 응답**: 상대 조회 경로를 아예 만들지 않는다 (RLS로 작성자 본인만)
- **Dependencies**: Supabase(Postgres, RLS, Realtime), 푸시 알림, 로컬 타임존 기준 일정 처리
