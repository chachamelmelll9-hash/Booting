# Wireframe: Tab 내 정보

## Overview

- Tab: 내 정보
- Pages: 5 신규 (마이페이지, 부모님 프로필 상태, 부모님 프로필 수정, 차단한 사용자, 신고 내역) + 재사용 설정 화면 19개
- Source Features: 부모님 프로필 등록 & 동의 (+ 공통, 조건 기반 추천 & 탐색)

## Feature: 부모님 프로필 등록 & 동의

### 1. 마이페이지

- **Route**: `app/(tabs)/profile/index.tsx`
- **Type**: Tab
- **Pattern**: 고유 (허브)
- **Reuse**: Existing — 상단 부모님 카드와 안전 항목 2개를 추가

**Annotations:**

- [2] 상태 배지: 공개 중 / 검수 중 / 비공개 / 반려 — 배지 색 + 텍스트 병행
- [3] 프로필이 없으면 카드 자리에 `부모님 등록하기` CTA 카드가 온다
- [4] 안전 섹션은 신규. 차단·신고는 설정 하위가 아니라 **독립 섹션**으로 노출한다 (PRD 14장 안전 기능의 접근성)
- [5] 로그아웃/회원 탈퇴는 구분선 아래로 **공간적으로 분리**. 회원 탈퇴만 위험색
- **Visual Hierarchy**: 부모님 카드 > 상태 배지 > 안전 섹션 > 계정 섹션 > 앱 섹션 > 탈퇴
- **Spacing**: 카드↔첫 섹션 24 / 섹션 간 32 / 행 높이 56 / 좌우 16

### 2. 부모님 프로필 상태

- **Route**: `app/(tabs)/profile/parent.tsx`
- **Type**: Stack
- **Pattern**: 상세형

#### Default State — 공개 중

```
+----------------------------------+
|  < 뒤로    부모님 프로필           |
+----------------------------------+
|                                  |
|  +----------------------------+  |
|  | 공개 중                     |  |  <- 상태 배지 (가장 큼, 20sp)
|  |                            |  |
|  | 프로필이 공개되어 추천에       |  |  <- 지금 무슨 상태인지 한 문장
|  | 노출되고 있어요.             |  |
|  +----------------------------+  |
|                                  |
|  인증 상태                        |
|  (v) 자녀 본인인증        완료     |
|  (v) 가족관계 인증        완료     |
|  (v) 부모님 등록 동의     완료     |
|  (v) 프로필 검수          완료     |
|                                  |
|  ------------------------------  |
|                                  |
|  프로필 미리보기                   |
|  +----------------------------+  |
|  |                            |  |
|  |        [img] 대표사진        |  |  <- 실제 공개되는 카드 그대로
|  |  텃밭지기, 67세             |  |
|  |  서울 송파구 · 사별          |  |
|  |  [여행·취미 친구][진지한 연애] |  |
|  +----------------------------+  |
|         [ 전체 보기 ]             |
|                                  |
|  ------------------------------  |
|                                  |
|  부모님 동의                       |
|  2026년 8월 20일 문자 인증         |
|  부모님은 언제든 철회하실 수 있어요.  |
|                    [ 철회 요청 ]  |
|                                  |
+----------------------------------+
|  [====프로필 수정====]            |
|  [ 프로필 공개 중단 ]              |  <- 위험색 아웃라인
+----------------------------------+
```

#### State — 검수 중

```
|  +----------------------------+  |
|  | 검수 중                     |  |
|  |                            |  |
|  | 운영팀이 프로필을 확인하고     |  |
|  | 있어요. 보통 1일 이내에       |  |
|  | 끝나요.                     |  |
|  +----------------------------+  |
|  ...
+----------------------------------+
|  [ 프로필 수정 ]                  |  <- 검수 중에는 수정이 Secondary
+----------------------------------+
```

#### State — 반려

```
|  +----------------------------+  |
|  | 반려됨                      |  |  <- 위험색 배지
|  |                            |  |
|  | 사진에 얼굴이 보이지 않습니다.  |  |  <- 구체적 사유
|  | 수정 후 다시 제출해주세요.     |  |
|  +----------------------------+  |
|  ...
+----------------------------------+
|  [====수정하고 다시 제출====]      |
+----------------------------------+
```

**Annotations:**
- [1] **상태 배지 → 다음에 할 일 한 문장 → 상세** 순서. 검수 중인데 `수정하기`가 가장 크면 안 된다
- [2] 상태에 따라 CTA의 위계가 바뀐다: 공개 중 = `수정` Primary, 검수 중 = `수정` Secondary, 반려 = `수정하고 다시 제출` Primary
- [3] `철회 요청`은 부모님의 권리다. 숨기지 않고 동의 섹션 안에 항상 노출한다
- [4] `공개 중단`·`철회 요청` 모두 Destructive Confirm 사용. 본문에 "받은 하트와 대화는 유지됩니다" 명시
- [5] 미리보기는 **실제 공개되는 카드와 같은 컴포넌트**를 쓴다 (따로 만들면 어긋난다)
- **Visual Hierarchy**: 상태 배지 > 상태 설명 > CTA > 인증 상태 > 미리보기 > 동의 이력

### 3. 부모님 프로필 수정

- **Route**: `app/(tabs)/profile/parent-edit.tsx`
- **Type**: Stack
- **Pattern**: 폼형

#### Default State

```
+----------------------------------+
|  < 뒤로    프로필 수정             |
+----------------------------------+
|                                  |
|  수정할 항목을 선택하세요           |
|                                  |
|  기본정보                     (>) |  <- 섹션 단위 진입
|  이름 · 나이 · 지역               |
|                                  |
|  사진                    4장 (>) |
|  대표사진 포함 최대 5장            |
|                                  |
|  혼인·가족                    (>) |
|  사별 · 2019년 · 자녀 2명         |
|                                  |
|  종교·생활                    (>) |
|  무교 · 비흡연 · 가끔 음주         |
|                                  |
|  관계 목적                 2개 (>) |
|  여행·취미 친구, 진지한 연애        |
|                                  |
|  소개글                       (>) |
|  자녀 소개 · 찾는 분 · 한마디       |
|                                  |
|  사주 정보              비공개 (>) |
|                                  |
|  ------------------------------  |
|                                  |
|  (i) 사진과 소개글을 바꾸면         |
|      부모님 승인과 검수를 다시       |
|      받아야 해요.                 |
|                                  |
+----------------------------------+
```

**Annotations:**
- [1] 등록 때와 달리 **단계형이 아니라 섹션 목록**이다. 수정은 특정 항목만 고치러 오는 행위다
- [2] 각 행에 현재 값을 요약해 보여준다 (들어가 보지 않아도 알 수 있게)
- [3] 재승인이 필요한 변경(사진·소개글·혼인정보)은 미리 고지한다. 저장 시 확인 다이얼로그로 한 번 더
- [4] 섹션 폼 자체는 `(parent-setup)/profile-edit`와 **같은 컴포넌트**를 재사용한다
- **Visual Hierarchy**: 섹션 라벨 > 현재 값 요약 > 재승인 고지

## Feature: 조건 기반 추천 & 탐색 (안전)

### 4. 차단한 사용자

- **Route**: `app/(tabs)/profile/blocked.tsx`
- **Type**: Stack
- **Pattern**: 리스트형

#### Default State

```
+----------------------------------+
|  < 뒤로    차단한 사용자           |
+----------------------------------+
|                                  |
|  차단한 분의 프로필은 추천과        |
|  목록에 나타나지 않아요.           |
|                                  |
|  +------+ 최OO, 68세             |
|  | [img]| 인천 남동구             |
|  +------+ 8월 28일 차단  [ 해제 ] |
|                                  |
|  +------+ 강OO, 70세             |
|  | [img]| 서울 강서구             |
|  +------+ 8월 20일 차단  [ 해제 ] |
|                                  |
+----------------------------------+
```

**Annotations:**
- [1] 상단 한 줄로 차단의 효과를 설명한다 (사용자가 무엇을 되돌리는지 알게)
- [2] `해제`는 Destructive Confirm 없이 즉시 처리하되, 토스트에 `실행 취소` 5초 제공
- [3] 사진은 흑백 처리 — 차단 상태임을 색만이 아니라 라벨(`8월 28일 차단`)로도 표시

#### Empty State

Common State 사용 — "차단한 사용자가 없어요" (CTA 없음: 빈 상태가 정상 상태)

### 5. 신고 내역

- **Route**: `app/(tabs)/profile/reports.tsx`
- **Type**: Stack
- **Pattern**: 리스트형

#### Default State

```
+----------------------------------+
|  < 뒤로    신고 내역               |
+----------------------------------+
|                                  |
|  +----------------------------+  |
|  | 처리 완료                   |  |  <- 처리 상태가 리드
|  | 금전 요구                   |  |
|  | 최OO 님 · 8월 28일 접수      |  |
|  | 해당 계정에 이용 제한 조치를   |  |
|  | 적용했습니다.               |  |
|  +----------------------------+  |
|                                  |
|  +----------------------------+  |
|  | 확인 중                     |  |
|  | 사진 도용                   |  |
|  | 강OO 님 · 8월 30일 접수      |  |
|  +----------------------------+  |
|                                  |
+----------------------------------+
```

**Annotations:**
- [1] 처리 결과를 **구체적으로** 알린다. "처리되었습니다" 한 줄은 신뢰를 깎는다
- [2] 신고 대상의 개인정보는 공개 별명까지만
- [3] 접수 후 처리까지의 상태: 접수됨 → 확인 중 → 처리 완료

#### Empty State

Common State 사용 — "접수한 신고가 없어요" (CTA 없음)

## 재사용 화면 (와이어프레임 생략)

다음은 보일러플레이트를 그대로 쓰고 **문구만 교체**한다. 레이아웃 변경이 없어 와이어프레임을 그리지 않는다.

`app-settings.tsx`, `notification-settings.tsx`, `info.tsx`,
`account/password.tsx`, `account/phone.tsx`,
`app-info/about.tsx`, `app-info/agreement.tsx`, `app-info/company.tsx`,
`help/index.tsx`, `help/faq.tsx`, `help/guide.tsx`, `help/notice.tsx`, `help/policy.tsx`,
`notifications/message-preferences.tsx`, `preferences/language.tsx`, `preferences/permissions.tsx`,
`support/contact.tsx`, `support/feedback.tsx`

**변경이 필요한 재사용 화면 1개:**

- `account/personal-data.tsx` — 하단에 **회원 탈퇴**와 **부모님 동의 철회 요청** 항목 추가 (PRD 13.8). 두 항목 모두 Destructive Confirm 사용, 회원 탈퇴는 확인 문구 입력 요구

## Tab Navigation Flow

```
[내 정보: 마이페이지]
   |
   +--프로필 관리--> [부모님 프로필 상태]
   |                     |
   |                     +--수정--> [부모님 프로필 수정] --섹션--> [(parent-setup)/profile-edit 폼 재사용]
   |                     |
   |                     +--전체 보기--> [(parent-setup)/preview]
   |                     |
   |                     +--공개 중단/철회--> [Destructive Confirm] --> (상태 갱신)
   |
   +--차단한 사용자--> [blocked]
   +--신고 내역------> [reports]
   +--안전 가이드----> [WebView /safety]
   +--(프로필 없음) 부모님 등록하기--> [(parent-setup)/onboarding]
   +--기존 설정 화면들 (재사용)
```
