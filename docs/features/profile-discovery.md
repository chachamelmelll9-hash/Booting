# Feature: 조건 기반 추천 & 탐색

## User Goal

자녀가 우리 부모님과 어울릴 만한 상대 부모님을 생활권·조건 기준으로 훑어보고, 관심 가는 분에게 하트를 보내거나 넘긴다.

## Summary

부모님의 **거주 생활권**(실시간 GPS가 아니다)을 기준으로 설정한 반경 안의 공개 프로필을 카드로 추천한다. 반경은 10 / 30 / 50km / 전국 중 선택하고 기본값은 30km다(TODO-06). 카드에는 대표사진·별명·나이·거주지역(시·군·구)·사별/이혼 여부·관계 목적 최대 2개·대표 취미·소개글 일부·인증 배지만 간결하게 싣는다. 자녀 수와 동거 가족은 민감도가 높아 **필터로 쓰지 않고 상세에서만** 보여준다. 카드에서 할 수 있는 행동은 하트 / 넘기기 / 상세보기 / 신고 / 차단이며, 차단한 사용자·이미 넘긴 프로필·정책상 비공개 프로필은 추천에서 제외한다. 관계 목적이 겹치는 프로필을 우선 노출한다. **'동성 친구'를 선택한 경우에는 같은 성별이면서 동성 친구를 찾는 프로필만** 추천하고(성별 필터보다 이 규칙이 우선한다), 반대로 목적이 '동성 친구' 하나뿐인 프로필은 이성 회원의 추천에 나오지 않는다.

## User Journey

### Step 1: 발견 — 홈 탭이 곧 추천 피드

- **사용자가 보는 것**: 홈 탭 진입 시 첫 카드가 화면 대부분을 차지. 상단에 현재 필터 요약 칩("30km · 서울 송파구 · 사별·이혼"), 우상단 필터 아이콘. 첫 실행 시 카드 위에 1회성 툴팁 — "오른쪽으로 밀면 관심, 왼쪽은 다음에"
- **사용자가 하는 것**: 툴팁 닫기, 카드 훑어보기
- **시스템 피드백**: 툴팁은 1회만 표시(로컬 저장), 이후 미표시
- **시각적 위계**: 대표사진 → 이름·나이 → 거주지역·혼인상태 → 관계 목적 칩 → 소개글 일부 → 인증 배지
- **States**:
  - **조작**: 카드를 좌우로 스와이프하면 넘기기/관심이 되고, 같은 동작을 하단 버튼으로도 할 수 있다. **스와이프 전용으로 만들지 않는다** — 손 떨림이 있는 사용자가 앱 자체를 못 쓰게 된다 (S11.4가 탭만으로 완주하는 걸 검증한다). 받은 관심 목록도 같은 덱을 쓴다: 목록으로 쌓아 두면 한 명씩 제대로 보지 않고 훑어 넘기게 된다.
- **빈 상태에는 현재 조건을 함께 표시한다** — "조건에 맞는 분이 없습니다"만 있으면 사용자는 앱이 고장난 줄 안다. `현재 조건: 남성 · 50~60세 · 전국`처럼 무엇 때문에 비었는지 보여줘야 고칠 수 있다.
- **저장된 조건이 없으면 이성이 기본값**이다 (동성 친구 목적이면 추천 단계에서 무시되고 같은 성별이 강제된다).
- Loading: 카드 형태 스켈레톤 1장 + 하단 액션 버튼 비활성
  - Empty: "조건에 맞는 분을 찾지 못했어요" + 서브 "추천 거리를 넓히거나 조건을 조정해보세요" + `조건 변경하기`
  - Error: "추천을 불러오지 못했어요. 다시 시도해주세요." + `다시 시도`
  - Success: 카드 스택 렌더

### Step 2: 진입 — 추천 조건 설정

- **사용자가 보는 것**: 바텀시트 필터 — 원하는 상대 성별 / 연령 범위 / 거주지역 / 추천 거리(10·30·50km·전국) / 혼인 상태(사별만·이혼만·모두) / 관계 목적 / 종교 / 음주 / 흡연 / 현재 경제활동
- **사용자가 하는 것**: 조건 조정 후 `적용`
- **시스템 피드백**: 적용 즉시 피드 재조회, 상단 칩 갱신, "조건을 적용했어요" 토스트
- **시각적 위계**: 추천 거리(가장 큰 영향) → 연령 범위 → 혼인 상태 → 나머지 접이식
- **States**:
  - Loading: `적용` 버튼 스피너
  - Empty: 적용 결과 0건이면 시트를 닫지 않고 "이 조건에 맞는 분이 없어요. 거리를 넓혀볼까요?" + `전국으로 넓히기`
  - Error: "조건을 저장하지 못했어요. 다시 시도해주세요."
  - Success: 필터 칩 갱신 + 피드 갱신

### Step 3: 입력/선택 — 스와이프와 액션

- **사용자가 보는 것**: 카드 하단 고정 액션 3개 — `넘기기` / `상세보기` / `하트`. 카드 우상단 ⋯ 메뉴에 신고·차단 (신고는 차단을 포함한다 — 접수 즉시 추천과 대화에서 빠진다)
- **사용자가 하는 것**: 좌우 스와이프 또는 버튼 탭. 하트는 확인 없이 즉시 전송
- **시스템 피드백**: 하트 → 카드가 위로 빠지며 "관심을 보냈어요" 토스트. 넘기기 → 다음 카드. 두 경우 모두 되돌리기 없음(넘긴 프로필은 재추천 제외)
- **시각적 위계**: `하트`가 주 액션(가장 크고 강조색) → `상세보기` 보조 → `넘기기` 가장 약함
- **States**:
  - Loading: 하트 전송 중 버튼 비활성 + 스피너(중복 전송 방지)
  - Empty: 스택 소진 시 "오늘 추천을 모두 확인했어요" + "조건을 넓히면 더 많은 분을 만날 수 있어요" + `조건 변경하기`
  - Error: "관심을 보내지 못했어요. 잠시 후 다시 시도해주세요." (카드는 스택에 남긴다)
  - Error(중복): "이미 관심을 보낸 분이에요"
  - Success: 토스트 + 다음 카드 전환

### Step 4: 결과 확인 — 상세 프로필

- **사용자가 보는 것**: 사진 캐러셀(최대 5장) → 별명·나이·거주지역 → 인증 배지 → 관계 목적 → 소개글 3종(자녀가 쓴 소개 / 이런 분을 찾아요 / 부모님의 한마디) → 생활정보(**키**·종교·직업·음주·흡연) → **자녀 수·동거 가족**(이 화면에서만) → 사주(공개 설정한 경우만)
- **인증 배지는 3종만**: 자녀 인증 / 가족관계 / 부모님 동의. **검수 완료는 어느 화면에도 띄우지 않는다** — 내부 심사 상태이지 사용자에게 주는 정보가 아니다. 남에게는 중복(공개된 프로필은 이미 검수를 통과했다)이고, 내 프로필 화면에서도 '공개 중' 표시가 같은 말을 이미 하고 있다. 서버 DTO 에는 `badges.review` 가 남아 있지만 화면에는 쓰지 않는다.
- **경제 활동은 별도 줄로 두지 않는다**: 직업 문구에 `(은퇴)`로 합친다. 따로 두면 "직업: 교사"와 "경제 활동: 하지 않으십니다"가 모순으로 읽힌다.
- **사용자가 하는 것**: 스크롤로 읽고 하단 고정 바에서 하트/넘기기, 상단 ⋯에서 신고·차단
- **시스템 피드백**: 하트 시 상세를 닫고 피드로 복귀 + 토스트
- **시각적 위계**: 대표사진 → 자녀가 쓴 소개글(이 서비스의 차별점) → 인증 배지 → 관계 목적 → 생활정보 → 가족정보
- **States**:
  - Loading: 사진 자리 스켈레톤 + 텍스트 라인 스켈레톤
  - Empty: 선택 항목 미입력 시 해당 섹션 자체를 숨긴다(빈 값 노출 금지)
  - Error: "프로필을 불러오지 못했어요." + `다시 시도`
  - Error(비공개 전환): "이 프로필은 현재 공개되지 않았어요" + `목록으로`
  - Success: 전체 렌더

### Step 5: 후속 행동 — 신고 / 차단

- **사용자가 보는 것**: 신고 사유 선택 바텀시트(허위 정보 / 사진 도용 / 금전 요구 / 투자·상품 권유 / 성적 불쾌감 / 기타) + 선택 입력 상세, 차단은 확인 다이얼로그
- **사용자가 하는 것**: 사유 선택 후 제출, 또는 차단 확인
- **시스템 피드백**: "신고를 접수했어요. 확인 후 조치해드릴게요." / "차단했어요. 이 분의 프로필은 더 이상 보이지 않아요."
- **시각적 위계**: 사유 목록 → 상세 입력(선택) → `신고하기`(경고색)
- **States**:
  - Loading: 제출 버튼 스피너
  - Error: "신고를 접수하지 못했어요. 다시 시도해주세요."
  - Success: 토스트 + 해당 프로필 즉시 피드에서 제거

### Step 6: 이탈/완료

- **사용자가 보는 것**: 탭 이동으로 자연 이탈. 스택 위치는 세션 간 유지하지 않고 매 진입 시 재조회
- **시스템 피드백**: 넘김/하트 이력은 서버에 남아 재추천에서 제외
- **States**:
  - Success: 다음 진입 시 새 후보만 노출

## Visual Hierarchy Notes

- 카드에서 가장 먼저 봐야 할 정보 1가지: **대표사진**. 그다음이 별명·나이 한 줄.
- 상세에서 가장 먼저 봐야 할 정보 1가지: **자녀가 쓴 소개글**. 일반 소개팅 앱과 다른 지점이므로 스펙·조건보다 위에 둔다.
- 인증 배지는 신뢰의 근거라 카드·상세 양쪽에서 접히지 않는 고정 위치에 둔다.
- CTA 레이블: `하트 보내기`, `다음에 볼게요`, `프로필 자세히 보기`, `조건 변경하기`.

## Consistency Checklist

- [ ] 프로필 카드 컴포넌트를 추천/받은 하트/인연 관리에서 공유한다
- [ ] 하트 버튼의 모양·색·피드백이 모든 화면에서 동일하다
- [ ] 신고/차단 진입점이 카드·상세·채팅방에서 같은 위치(우상단 ⋯)에 있다
- [ ] 빈 상태 카피는 "왜 비었는지 + 무엇을 하면 되는지" 2줄 패턴을 따른다

## Accessibility Notes

- 스와이프만으로 조작 가능한 기능을 두지 않는다 — 하트/넘기기는 **버튼으로도** 반드시 제공
- 터치 타겟 최소 44×44px (카드 하단 액션은 56px 권장)
- 텍스트 대비 4.5:1 이상, 사진 위 텍스트는 그라디언트 오버레이로 대비 확보
- 관계 목적 칩은 색 + 텍스트 병행, 색만으로 구분하지 않는다
- 카드에 accessibilityLabel 요약 제공("텃밭지기, 67세, 서울 송파구, 사별, 여행·취미 친구")

## Technical Notes

- **Processing**: Server-side (추천 후보 산출·제외 필터·정렬), 클라이언트는 카드 스택 렌더와 낙관적 전환만
- **Data Flow**: 필터 + 우리 부모님 생활권 좌표 → 서버 추천 쿼리(반경·조건·제외목록) → 카드 배치(페이지 단위 프리페치) → 하트/넘김 이벤트 기록 → 다음 조회에서 제외
- **제외 규칙**: 차단(양방향) / 이미 넘김 / 이미 하트 보냄 / 비공개·검수중·신고 검토중 / 미활동 60일 초과(TODO-11) / 본인 부모님
- **정렬**: 관계 목적 교집합 수 → 거리 → 최근 활동 순
- **Dependencies**: Supabase Postgres(위치는 시·군·구 코드 + 대표 좌표, PostGIS 불필요 시 하버사인), Storage 서명 URL, RLS로 비공개 프로필 차단
