# Feature: 하트 & 대화 연결

## User Goal

우리 부모님께 관심을 보낸 분들을 확인하고, 서로 관심이 맞은 상대의 자녀와 대화를 시작해 부모님께 소개할지 판단한다.

## Summary

받은 하트는 '우리 부모님께 관심을 보낸 분' 목록에 쌓인다. 자녀가 그 목록에서 상대 프로필을 확인하고 하트를 되돌려주면 **상호 하트**가 성립하고, 그 시점에 자녀 간 1:1 메시지가 열린다. 이 서비스에서 상호 하트는 '매칭 성공'이 아니라 **'대화 연결'**이며, 알림·화면 어디에서도 '매칭 성공'이라는 표현을 쓰지 않는다(PRD 10.1·16장). 대화는 부모님이 아니라 자녀끼리 먼저 하고, 자녀가 상대를 확인한 뒤 각자 부모님께 소개한다. 채팅방에서는 신고·차단을 바로 쓸 수 있어야 하고, 외부 연락처를 주고받기 전에 안전수칙을 안내한다. 금전 요구·계좌·투자 권유 문구 감지 경고는 P1로 분류한다.

## User Journey

### Step 1: 발견 — 받은 하트 탭의 배지

- **사용자가 보는 것**: 하단 탭 `받은 하트`에 읽지 않은 개수 배지. 푸시 알림 "우리 부모님께 관심을 보낸 분이 있어요"
- **사용자가 하는 것**: 탭 진입
- **시스템 피드백**: 진입 시 배지 해제(개별 항목의 읽음 처리는 상세 진입 시)
- **시각적 위계**: 신규 하트(강조 배경) → 확인한 하트 → 지난 하트
- **States**:
  - Loading: 리스트 스켈레톤 3행
  - Empty: "아직 받은 관심이 없어요" + "우리 부모님 프로필이 공개되어 있으면 더 많은 분이 볼 수 있어요" + `프로필 상태 보기`
  - Error: "목록을 불러오지 못했어요." + `다시 시도`
  - Success: 카드 리스트

### Step 2: 진입 — 받은 하트 목록

- **사용자가 보는 것**: 세로 리스트. 각 행에 대표사진 썸네일 · 별명 · 나이 · 거주지역 · 관계 목적 2개 · 인증 배지 · 받은 시각
- **사용자가 하는 것**: 행 탭 → 상세, 또는 행에서 바로 `하트`/`넘기기`
- **시스템 피드백**: 하트 → 상호 하트 성립 시 즉시 축하 시트, 아니면 목록에서 제거
- **목록에 남지 않는 것**: **이미 인연이 된 상대**(상호 하트 이후)와 차단한 상대. 인연이 성립하는 순간 그 관계는 '인연' 탭으로 옮겨간다 — 받은 관심에 남겨 두면 이미 대화 중인 사람에게 아직 답할 게 남은 것처럼 보이고, 다시 하트를 누르면 중복 하트로 거부만 된다. 안 읽음 배지도 같은 기준으로 센다 (목록은 비었는데 배지만 남는 상태를 만들지 않는다)
- **시각적 위계**: 사진 → 이름·나이 → 지역·혼인상태 → 관계 목적 → 배지
- **States**:
  - Loading: 스켈레톤
  - Empty: 위와 동일
  - Error: "관심을 보내지 못했어요. 잠시 후 다시 시도해주세요."
  - Success: 상호 하트면 축하 시트, 아니면 조용히 제거

### Step 3: 결과 — 상호 하트 = 대화 연결

- **사용자가 보는 것**: 전체 화면 시트 — 상단 카피 **"서로 관심이 있어요"**, 양측 부모님 대표사진 2장, 본문 "이제 자녀분들끼리 대화를 시작할 수 있어요. 부모님께 소개하기 전에 서로를 확인해보세요.", 기본 CTA `대화 시작하기`, 보조 `나중에`
- **사용자가 하는 것**: `대화 시작하기` → 채팅방 진입
- **시스템 피드백**: 채팅방 생성, 매칭 탭에 '대화 연결' 상태로 편입. 관심과 함께 보낸 **인사말이 대화방 첫 메시지로 옮겨간다** — 빈 채팅방에서 말을 트는 부담 때문에 거기서 멈추는 경우가 많다. **양쪽 인사말이 모두 옮겨졌으면 상태가 곧바로 '대화 중'** 이다 (인사말은 메시지 전송 경로를 타지 않으므로 여기서 따로 올려야 한다)
- **시각적 위계**: "서로 관심이 있어요" 문구 → 두 사진 → 다음 행동 설명 → CTA
- **States**:
  - Error: "대화방을 열지 못했어요. 매칭 탭에서 다시 시도해주세요."
  - Success: 채팅방 진입
- **금지**: 이 화면과 관련 알림에 '매칭', '매칭 성공' 문구를 쓰지 않는다
- **뒤로가기**: 이 시트에서 대화방으로 바로 들어와도 그 아래에 **매칭 목록이 깔려 있어야** 한다 (`withAnchor`). 없으면 뒤로가기가 탭 네비게이터까지 올라가 홈 탭으로 튄다. 대화방은 하드웨어 뒤로가기도 가로채 항상 매칭 목록으로 보낸다 — 실제로 대부분 이쪽으로 나간다

### Step 4: 후속 행동 — 자녀 간 1:1 메시지

- **사용자가 보는 것**: 채팅방. 상단에 상대 부모님 요약 바(사진·성명·나이·`프로필 보기`), 우상단 ⋯(`대화 상대 신고하기` / `대화방 나가기`). 최초 진입 시 상단에 안전 안내 배너 — "전화번호 등 연락처는 충분히 확인한 뒤 공유해주세요."
- **사용자가 하는 것**: 텍스트 메시지 송수신, 프로필 재확인, 필요 시 신고(금전 요구 / 부적절한 언행 / 사기 의심)
- **시스템 피드백**: 전송 즉시 낙관적 렌더 후 서버 확인 시 체크 표시. 실패 시 해당 말풍선에 재시도 아이콘
- **시각적 위계**: 상대 요약 바 → 대화 내용 → 입력창 → 안전 배너(1회 표시 후 접힘)
- **States**:
  - Loading: 최초 진입 시 메시지 스켈레톤, 이전 대화 불러오기 인디케이터
  - Empty: "대화를 시작해보세요" + 추천 첫 문장 3개 칩("어머니 사진 잘 봤습니다", "취미가 비슷하시네요", "부모님은 어떤 분이신가요?")
  - Error(전송): 말풍선 옆 "전송 실패 · 다시 시도"
  - Error(권한): "이 대화방에 접근할 수 없어요. 상대방이 대화를 종료했을 수 있어요."
  - Error(차단): "차단된 사용자와는 대화할 수 없어요."
  - Success: 말풍선 전송 완료 표시
- **P1**: 금전 요구·계좌번호·투자 권유 패턴 감지 시 대화 상단에 경고 배너

### Step 5: 후속 행동 — 인연 관리에서 상태 추적

- **사용자가 보는 것**: `인연` 탭의 상태별 목록 — 서로 관심이 있어요 / 대화 중 / 부모님 의사 확인 중 / 만남 예정 / 만남 확인 대기 / 매칭 성공
- **사용자가 하는 것**: 상태별 필터 탭 이동, 항목 탭으로 채팅방 또는 만남 화면 진입
- **시스템 피드백**: 상태 전이 시 목록 자동 이동 + 해당 항목에 상태 배지
- **시각적 위계**: 상태 배지 → 상대 부모님 사진·이름 → 마지막 메시지/다음 할 일 → 시각
- **States**:
  - Loading: 리스트 스켈레톤
  - Empty(상태별): "아직 이 단계의 인연이 없어요" + 이전 단계로 유도하는 CTA
  - Error: "목록을 불러오지 못했어요." + `다시 시도`
  - Success: 상태별 그룹 렌더

### Step 6: 이탈 — 대화 종료 / 신고

- **사용자가 보는 것**: ⋯ 메뉴의 `대화방 나가기`(확인 다이얼로그) 또는 `대화 상대 신고하기`(같은 시트가 사유 선택으로 바뀐다)
- **시스템 피드백**: 대화방 나가기 → 매칭 목록에서 제거, 상대에게는 "상대방이 대화를 종료했어요" 표시. **신고는 차단을 포함한다** → 접수와 동시에 인연이 종료되고 그 대화는 양쪽 매칭 목록에서 사라지며 추천에도 다시 뜨지 않는다. 사유는 `내 정보 > 신고 내역`에 남는다
- **`ended` 로만 두지 않는 이유**: 상태만 바꾸면 "대화 종료" 카드로 목록에 계속 남아, 신고한 사람 눈에는 신고가 아무 일도 하지 않은 것으로 보인다 (`connections.list` 가 차단 쌍을 걸러낸다)
- **States**:
  - Error: "요청을 처리하지 못했어요. 다시 시도해주세요."
  - Success: "대화를 종료했어요." / "신고가 접수되었습니다. 내 정보 > 신고 내역에서 확인하실 수 있습니다."

## Visual Hierarchy Notes

- 상호 하트 화면에서 가장 먼저 봐야 할 정보 1가지: **"서로 관심이 있어요"** 문구. 이 단계가 '성공'이 아니라 '시작'임을 문구 자체가 말해야 한다.
- 채팅방에서 가장 먼저 봐야 할 정보 1가지: 상대 **부모님 요약 바**. 자녀끼리 대화하지만 대화의 주제는 부모님이다.
- 인연 관리에서는 상태 배지가 제목보다 크게 읽혀야 한다 — 사용자가 "지금 뭘 해야 하나"를 이 화면에서 판단한다.
- CTA 레이블: `대화 시작하기`, `하트 보내기`, `프로필 보기`, `대화 나가기`.

## Consistency Checklist

- [ ] 하트 액션의 모양·색·토스트가 추천 피드와 동일하다
- [ ] 신고 진입점이 항상 우상단 ⋯ 이다 (카드·상세·채팅방). 차단은 프로필 신고 화면에만 둔다
- [ ] 상태 배지 문구가 PRD 10.3 목록과 글자 단위로 일치한다
- [ ] '매칭 성공' 문구가 상호 하트 단계 어디에도 없다

## Accessibility Notes

- 터치 타겟 최소 44×44px — 리스트 행 인라인 하트/넘기기 버튼 포함
- 메시지 말풍선 대비 4.5:1 이상, 보낸/받은 구분을 색만으로 하지 않고 정렬 + 꼬리 방향 병행
- 전송 실패는 아이콘 + 텍스트("전송 실패 · 다시 시도")
- 읽지 않은 배지는 숫자 + accessibilityLabel("읽지 않은 관심 3개")

## Technical Notes

- **Processing**: Server-side (하트 기록·상호 하트 판정·채팅방 생성 권한), 실시간 메시지는 Supabase Realtime 구독
- **Data Flow**: 하트 전송 → 서버가 역방향 하트 존재 확인 → 존재하면 대화방(conversation) 생성 + 양측에 알림 → 메시지 송수신 → 상태 전이 이벤트가 인연 관리 목록에 반영
- **상태 기계**: `관심 보냄` → `서로 관심이 있어요` → `대화 중` → `부모님 의사 확인 중` → `만남 준비` → (첫 만남 기능으로 인계)
- **접근 제어**: 대화방은 참여자 2인에게만 RLS로 열고, 차단 시 즉시 접근 차단
- **보관**: 최종 매칭 성립 후 채팅방 90일 유지(TODO-12)
- **Dependencies**: Supabase(Postgres, Realtime, RLS), 푸시 알림

## Decision Log

| Question | Choice | Reason |
|----------|--------|--------|
| 상호 하트의 명칭 | '서로 관심이 있어요' / '대화 연결' | PRD 10.1 — '매칭 성공'은 부모님이 실제로 만난 뒤에만 쓴다 |
| 관심 보내기 = 인사말 작성 | 하트 버튼(또는 오른쪽 스와이프)을 누르면 바로 보내지 않고 인사말 시트를 연다. 확인 다이얼로그가 아니라 **작성 단계**이며, 비워 두고 보내면 인사말 없는 관심이 된다 | 사용자 결정(2026-09-01). 별도 버튼으로 분리하면 아무도 쓰지 않는 기능이 된다 |
| 인사말 → 첫 메시지 | 상호 하트가 되면 양측 인사말을 **보낸 시각 순서대로** 대화방에 복사한다 | 빈 채팅방에서 먼저 말을 트는 부담이 대화 이탈의 가장 큰 이유다. 이미 건넨 한마디가 남아 있으면 그 지점이 없어진다 |
| 인사말 노출 시점 | 매칭 전에도 **받은 관심 카드에 표시**한다 | 답할지 판단할 근거가 필요하다. 대신 200자로 묶고 신고 경로를 함께 둔다 |
| 인사말 이관 실패 | 인연은 그대로 두고 경고 로그만 남긴다 | 인사말 복사가 실패했다고 매칭 자체를 되돌리면 손해가 더 크다 |
