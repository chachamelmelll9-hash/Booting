## Design Decisions

### Layout Patterns

| Pattern | 화면 | 공통 규칙 |
|---|---|---|
| 리스트형 | 받은 하트, 인연 목록, 차단 목록, 신고 내역, 알림 | `FlatList` 필수. **상태에 따라 행 구성을 다르게** 한다 (동일 카드 반복 금지) |
| 상세형 | 상대 부모님 상세, 부모님 프로필 상태, 만남 일정 | 라벨-값 2열. 미입력 섹션은 통째로 숨김 |
| 폼형 | 추천 조건, 프로필 작성/수정, 부모님 동의, 인증, 미동행 확인, 신고 | 라벨은 필드 위, 에러는 필드 아래, helper text는 영구 노출 |
| 결과형 | 상호 하트 시트, 만남 확인, 사후 응답 | 상태 문구가 최상위. 점수·평가 요소 금지 |
| 고유 | 추천 피드(카드 스택), 채팅방, 마이페이지, 등록 안내, 미리보기, 부모님 의사 | 개별 설계 |

### Primary CTA Style

- 주 액션은 하단 Sticky, 높이 56pt, 폭 100%. 화면당 **하나만** Primary
- 보조 액션은 Secondary(아웃라인), 회피 경로는 Ghost
- 파괴적 액션은 위험색 + 구분선 아래로 공간 분리 + 확인 다이얼로그
- **균등 분할 금지**: 추천 피드 하단 3버튼은 `하트` > `자세히` > `넘기기` 순으로 폭·강조가 다르다

### Spacing (8dp grid)

화면 좌우 16 / 카드 내부 16 / 리스트 아이템 간 12 / 섹션 간 24 / 주요 섹션 분리 32 / 라벨↔값 4

### Anti-AI-Slop 적용 결과

| 회피한 패턴 | 이 앱에서의 처리 |
|---|---|
| 모든 것 중앙 정렬 | 빈 상태 화면만 중앙. 나머지는 전부 좌측 정렬 기준 |
| 균등 3열 카드 | 사진 그리드 2열, 생활정보 라벨-값 2열, 하단 액션 3개는 폭이 서로 다름 |
| 모든 리스트 동일 카드 | 받은 하트는 미읽음/읽음 구성이 다르고, 인연 목록은 상태마다 행 구성이 다르다 |
| 이모지를 아이콘으로 | 전 화면 벡터 아이콘 세트 |
| 동일 패딩 반복 | 섹션 간 24/32 차등, 카드 내부만 16 |
| linear 애니메이션 | 카드 스와이프·성공 체크 모두 스프링(`damping: 18`), 상호 하트 사진은 60ms 스태거 |
| 무한 반복 애니메이션 | 스켈레톤 시머 외 사용 안 함. 성공 화면에 컨페티 없음 |

### Common States

`wireframe-common-states.md` 참조 — Empty / Loading(스켈레톤) / Error / Inline Field Error / Destructive Confirm / Toast

## Decision Log

| Tab | Page | Question | Choice |
|-----|------|----------|--------|
| 홈 | 추천 피드 | 카드 하단 액션 배치 | `하트` 우세, `자세히` 보조, `넘기기` 최약 — 균등 3분할 회피 |
| 홈 | 추천 피드 | 스와이프 전용 조작 허용? | 불가. 하트/넘기기를 버튼으로도 반드시 제공 (a11y) |
| 홈 | 추천 피드 | 프로필 미등록 시 | 추천 API 미호출 + 3단계 안내 포함 빈 상태 |
| 홈 | 추천 조건 | 조건 순서 | 결과 영향 크기 순(거리→나이→혼인→목적), 나머지는 접힘 |
| 관심 | 받은 하트 | 미읽음/읽음 표현 | 미읽음은 큰 카드 + 인라인 액션, 읽음은 1행 컴팩트 |
| 인연 | 인연 목록 | 행의 리드 요소 | 상대 이름이 아니라 **상태 배지** — 이 화면의 판단은 "지금 뭘 해야 하나" |
| 인연 | 채팅방 | 상대 부모님 노출 | 상단 요약 바 상주 — 대화는 자녀끼리지만 주제는 부모님 |
| 인연 | 채팅방 | 안전 배너 | 최초 1회 후 접힘. 매 진입 노출은 무시된다 |
| 인연 | 미동행 확인 | 진행 버튼 위계 | Secondary. 권장 경로가 아님을 형태로 표현하고 `다시 생각해볼게요`를 위에 배치 |
| 인연 | 만남 확인 | 대기 상태 최상위 정보 | "상대방의 만남 확인을 기다리고 있어요" — 가장 헷갈리는 지점 |
| 인연 | 만남 확인 | 최종 매칭 렌더 시점 | 서버 응답이 `matched`일 때만. 낙관적 렌더 금지 |
| 인연 | 사후 응답 | 비공개 고지 | 자물쇠 아이콘 + 문구 상시 노출 — 없으면 솔직한 응답을 얻지 못한다 |
| 내 정보 | 마이페이지 | 부모님 카드 위치 | 설정 목록보다 위·크게. 이 탭의 주인공 |
| 내 정보 | 프로필 상태 | 상태별 CTA 위계 | 공개 중=수정 Primary / 검수 중=수정 Secondary / 반려=재제출 Primary |
| Modal | 상세 프로필 | 최상위 콘텐츠 | 스펙이 아니라 **자녀가 쓴 소개글** — 서비스의 차별점 |
| Modal | 상호 하트 | 문구 | "서로 관심이 있어요". '매칭'이라는 단어를 쓰지 않는다 (PRD 10.1) |
| Modal | 신고 | 함께 차단 | 기본 체크 |
| 등록 | 부모님 동의 | 기본 방식 | 문자(큰 카드) vs 대면(보조 버튼) — 위계로 권장 경로 표현 |
| 등록 | 부모님 동의 | 대면 동의 본문 | 부모님이 읽는 글이므로 17sp 이상·존댓말·짧은 문장 |
| 등록 | 프로필 작성 | 관계 목적 UI | 2개 선택 시 나머지 비활성, `아직 잘 모르겠어요`는 구분선으로 분리 |
| 등록 | 미리보기 | 렌더 방식 | 실제 추천 카드 컴포넌트 그대로 — 전용 UI를 만들면 실제와 어긋난다 |
| 전체 | UX 리뷰 | 리뷰 주체 | self (agent spawning disabled by session policy) — `mobile-ux-ui-design` 체크리스트 직접 적용 |
