# Feature: 사주 궁합 (무료)

> 기준 문서는 [prd.md 8.4](../../prd.md#84-사주-궁합) 다. 여기는 구현 쪽 정본이다.

## User Goal

자녀가 상대 부모님 프로필을 볼 때, 우리 부모님과 **사주가 어떻게 맞는지**를 함께 보고
관심을 보낼지 정한다. 궁합이 좋은 분부터 먼저 볼 수도 있다.

## Summary

양쪽 부모님의 생년월일·양음력·출생시각으로 **사주팔자 네 기둥**을 세워 궁합 점수(30~99)와
근거를 낸다. 전면 무료이고(TODO-10) 유료 전환·부분 공개 장치를 두지 않는다.
외부 유료 API 를 쓰지 않고 **서버에서 직접 계산한다** — 절기와 60갑자는 천문 계산이라
매번 같은 답이 나오고, 사람의 생년월일을 외부로 내보낼 이유도 없다.

## 어디에 보이는가

| 자리 | 보여주는 것 | 코드 |
|---|---|---|
| 추천 카드 (뒤집은 뒤) | `궁합 82 · 천생연분` 배지 | `GemCard` → `CompatibilityBadge` |
| 펼친 카드 | 같은 배지 | `ExpandedGemCard` |
| 받은 관심 카드 | 같은 배지 | 같은 컴포넌트 (서버가 `myProfileId` 를 넘긴다) |
| 상세 프로필 | 점수·등급·근거 최대 4줄·두 사람의 네 기둥 | `SajuCompatibilityCard` |
| 추천 조건 | `궁합 좋은 순` 정렬 + `최소 궁합`(50/60/70/80) | `FilterSheet` |
| 부모님 프로필 작성 | 양력/음력 · 태어난 시간 · 공개 여부 | `(parent-setup)/profile-edit` |

**인연 관리 탭에는 넣지 않는다.** 궁합은 "관심을 보낼까"를 정할 때 쓰는 정보이고,
이미 이어진 뒤에는 점수가 판단을 바꾸지 않는다. (서버 `toItems` 가 `viewerProfileId` 를
받을 때만 궁합을 싣는 것이 그 경계다.)

## 계산 — `apps/server/src/saju/lib/`

| 파일 | 역할 |
|---|---|
| `ganji.ts` | 천간·지지·오행 상수와 합·충·삼합·방합·원진 판정 |
| `solar-terms.ts` | 태양 겉보기황경 → 절기 시각, 율리우스일수 |
| `pillars.ts` | 사주팔자 네 기둥 |
| `compatibility.ts` | 궁합 점수·등급·근거 |

### 기둥 세우기

- **연주** — 입춘(황경 315°) 전이면 아직 지난 해다. 1월 1일생은 대부분 전년도 간지가 된다.
- **월주** — 12절(입춘부터 30° 간격)로 끊는다. 음력 초하루가 아니다. 월간은 오호둔(五虎遁).
- **일주** — 율리우스일수로 끊는 연속 60갑자. `korean-lunar-calendar` 의 일 간지와 대조해 맞췄다.
- **시주** — 23시부터 두 시간씩. 시간은 오서둔(五鼠遁). **23시 이후는 다음 날 자시**로 넘긴다(야자시).
- **음력 입력** — `korean-lunar-calendar`(한국천문연구원 기준, 1391~2050)로 양력으로 옮긴다.
  중국 농력이 아니라 KASI 음력을 쓰는 이유는 사용자가 대조할 만세력이 그쪽이기 때문이다.
- **표준시 보정** — 1954-03-21 ~ 1961-08-09 한국은 UTC+8:30 을 썼다. 이 시기에 적어 둔
  시계 시각을 KST 로 그냥 읽으면 30분이 밀려 시주가 통째로 어긋난다. 지금 만 65~72세인
  분들이 이 구간에 태어났다. (1908-04-01 ~ 1911-12-31 도 같다.)
- **경도 보정은 하지 않는다** — 서울 기준 −32분을 적용하는 유파가 있지만 한국천문연구원
  만세력은 표준시를 그대로 쓴다. 유파에 따라 갈리는 값을 서버가 임의로 고를 이유가 없다.

### 알려진 한계

절기 시각은 Meeus 저정밀 태양 위치식으로 구한다 — 황경 오차 약 0.01°, **시각으로 약 15분**.
절입과 15분 안쪽으로 태어난 경우 인쇄된 만세력과 월주가 갈릴 수 있다(확률 0.1% 미만).
정밀도를 더 올리려면 VSOP87 급수를 들여와야 하는데, 재미로 보는 참고 기능에 비해 표가 너무 크다.
**출생시각을 '모름'으로 두는 분이 더 많다는 점이 이 선택의 근거다.**

### 점수

기본 20점에 아래 항목을 더하고, 항목의 만점·최저점 합으로 **30~99** 에 정규화한다.

| 항목 | 배점 |
|---|---|
| 일간 (부부의 중심 자리) | 천간합 25 / 상생 18 / 비화 12 / 상극 7 / 충 4 |
| 일지 (배우자궁) | 육합 22 / 삼합 20 / 방합 14 / 동일 10 / 무관 6 / 충 −8 |
| 연지 (띠) | 삼합·육합 12 / 무관 5 / 충 −6 / 원진 −8 |
| 월지 (생활 리듬) | 합 8 / 무관 3 / 충 −5 |
| 오행 균형 (두 사람 합산 분포의 고름) | 0~18 |
| 음양 조화 (두 사람 합산) | 0~8 |
| 시지 (양쪽 다 시각을 알 때만) | 합 6 / 무관 2 / 충 −4 |

정규화 덕분에 **시주가 빠져도 점수가 깎이지 않는다** — 만점과 최저점이 함께 줄어든다.
대신 `confidence: 'medium'` 을 함께 내려보내고 화면이 "시주를 빼고 봤습니다"라고 밝힌다.

실측 분포(만 50세 이상 표본 2,016쌍): 최소 43 / 1사분위 64 / 중앙 69 / 3사분위 74 / 최대 92, 평균 69.0.
`distribution.spec.ts` 가 이 성질(뭉치지 않을 것, 40점 미만 5% 이하, 90점 이상 10% 이하)을 지킨다.

### 등급

`soulmate`(90+) / `excellent`(80+) / `good`(70+) / `fair`(60+) / `mixed`(그 외).
**낮은 쪽에 '나쁜 궁합'이라 쓰지 않는다** — 그 상대는 누군가의 부모님이고 자녀가 그 문장을 읽는다.

## 문구는 전부 모바일에 있다

서버는 **코드만** 내려보낸다: 점수, `SajuGrade`, `SajuReasonCode[]`, 천간·지지 **인덱스**.
한글은 `apps/mobile/src/shared/config/saju.ts` 한 곳에서 붙는다.
서버가 '갑자'라는 글자를 만들기 시작하면 같은 표가 양쪽에 생기고 언젠가 어긋난다.

## 프라이버시

- **`saju_infos.is_public` 은 생년월일·출생시각 자체의 노출만 가른다.** 궁합 계산은 이 값과
  무관하게 돈다 — 사주 칸을 둔 이유가 궁합이고(PRD 5.3), 점수와 근거 코드로는 생년월일이
  복원되지 않는다.
- **상대의 네 기둥은 상대가 공개했을 때만** 보낸다. 기둥 넷이면 60갑자 안에서 생년월일이
  거의 특정되므로, 비공개인 분의 기둥을 보내면 `saju` 를 숨긴 의미가 사라진다
  (`PublicProfileDto.sajuPillars.theirs`).
- 내 부모님 기둥은 내 데이터라 항상 보인다.

## 정렬·필터

- 궁합은 DB 가 모르는 값이라 SQL 로 정렬할 수 없다. `sort=compatibility` 이거나
  `minCompatibility` 가 걸리면 후보 **최대 200명**(`COMPATIBILITY_POOL`, 최근 활동 순)을
  받아 서버가 매기고 자른다. 홈이 하루 여섯 장이라 이 깊이면 충분하다.
- 이때 커서는 타임스탬프가 아니라 정렬된 목록의 **위치**(`o:20`)다. 정렬을 바꿔 커서 모양이
  안 맞으면 첫 페이지로 되돌린다.
- **우리 부모님 사주가 없으면 두 조건을 무시한다.** 그대로 적용하면 홈이 통째로 빈다 —
  사주를 안 적은 것이 사람을 못 보는 이유가 되면 안 된다.
- 최소 궁합을 걸면 **사주를 적지 않은 분도 함께 빠진다.** 조건 화면이 이 사실을 미리 알린다.

## 데이터

기존 `saju_infos` 를 그대로 쓴다 (새 컬럼 없음). 추가된 것은 조건뿐이다:

| 컬럼 | 값 |
|---|---|
| `discovery_filters.sort` | `recent`(기본) / `compatibility` |
| `discovery_filters.min_compatibility` | `null`(제한 없음) / 50 / 60 / 70 / 80 |

마이그레이션: `supabase/migrations/20260909120000_discovery_saju_sort.sql`

## 입력 화면

부모님 프로필 작성의 **선택 항목**이다.

- **날짜를 다시 묻지 않는다.** 기본정보의 생년월일을 그대로 쓰고 그것이 양력인지 음력인지만
  고른다. 날짜 칸이 둘이면 언젠가 어긋나고, 어느 쪽으로 사주를 세웠는지 아무도 설명하지 못한다.
- 태어난 시간은 숫자만 눌러도 된다 (`0730` → `07:30`). 콜론을 직접 치게 하면 숫자 키패드에서
  자판을 바꿔야 해서 이 나이대의 자녀분들이 가장 자주 멈추는 자리가 된다.
- '입력 안 함'을 고르면 `saju: null` 로 저장 요청이 가고 서버가 행을 지운다. 선택 항목은
  되돌릴 수 있어야 한다.
- 사주는 프로필을 저장할 때마다 함께 보낸다. 사주 칸을 건드렸을 때만 보내면 생년월일만
  고친 뒤에 사주가 옛 날짜로 남아 궁합이 엉뚱하게 나온다.
