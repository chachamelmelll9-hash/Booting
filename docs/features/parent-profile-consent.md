# Feature: 부모님 프로필 등록 & 동의

## User Goal

자녀가 자신이 실제 자녀임을 증명하고, 부모님께 직접 동의를 받아, 부모님을 잘 드러내는 프로필을 대신 만들어 공개 상태로 올린다.

## Summary

가입한 자녀가 휴대폰 본인인증 → 가족관계 인증 → 부모님 동의 → 프로필 작성 → 운영 검수 → 공개까지 한 줄기로 진행한다. 프로필은 자녀가 쓰지만 **공개 여부의 결정권은 부모님에게 있다** — 실제 공개될 화면을 부모님에게 그대로 보여주고 최종 승인을 받아야 공개된다. 동의는 부모님 휴대폰 문자 인증이 기본이고, 휴대폰이 없으면 자녀 단말에서 대면 동의(성함 + 동의 시각 기록)로 갈음한다(TODO-04). MVP에서 가족관계 심사는 자동 승인이며(TODO-05), 심사 상태 기계와 배지 표시는 실제 심사로 교체할 수 있도록 그대로 구현한다. 한 자녀가 등록할 수 있는 부모님은 1명이다(TODO-07). 등록 대상은 사별 또는 이혼으로 제한하고 별거는 가입 대상에서 제외한다. 부모님은 언제든 동의를 철회할 수 있고, 철회하면 프로필은 즉시 비공개가 된다.

## User Journey

### Step 1: 발견 — 가입 직후 "부모님 등록하기" 외에는 할 게 없다

- **사용자가 보는 것**: 홈 탭에 추천 카드 대신 큰 빈 상태 카드 — "아직 등록된 부모님이 없어요", 서브카피 "부모님 프로필을 등록해야 인연을 찾아드릴 수 있어요", 기본 CTA `부모님 등록하기`. 하단 탭은 보이되 홈 외 탭은 진입 시 같은 빈 상태로 유도.
- **사용자가 하는 것**: `부모님 등록하기` 탭
- **시스템 피드백**: 등록 플로우 스택으로 push, 진행률 표시(1/6)
- **시각적 위계**: 빈 상태 일러스트/아이콘 → 안내 문구 → CTA 버튼 → 서비스 원칙 3줄 요약
- **States**:
  - Loading: 등록 상태 조회 중 카드 자리 스켈레톤
  - Empty: 위 빈 상태가 곧 기본 화면
  - Error: "정보를 불러오지 못했어요. 다시 시도해주세요." + `다시 시도`
  - Success: 등록 완료 후 이 카드가 추천 피드로 대체됨

### Step 2: 진입 — 서비스 원칙 안내 + 가입 자격 확인

- **사용자가 보는 것**: 3장짜리 안내(자녀의 역할 / 부모님의 결정권 / 첫 만남은 자녀와 함께), 마지막 장에 혼인 상태 선택 — `사별` `이혼` `별거·기타`
- **사용자가 하는 것**: 넘기며 읽고 혼인 상태 선택
- **시스템 피드백**: `사별`/`이혼` → 다음 단계. `별거·기타` → 진행 차단 화면
- **시각적 위계**: 한 장에 한 메시지(큰 제목 + 한 문장) → 하단 고정 `다음`
- **States**:
  - Error(자격 미달): "법적으로 혼인 관계가 유지 중인 경우에는 등록할 수 없어요. 사별 또는 이혼인 경우에만 이용할 수 있습니다." + `돌아가기` (계정은 유지, 재시도 가능)
  - Success: 선택값이 이후 프로필 기본값으로 이월

### Step 3: 입력 — 자녀 본인인증 + 가족관계 인증

- **사용자가 보는 것**: 2단계 체크리스트(① 본인인증 ② 가족관계 인증), 각 항목의 상태 배지(미완료/진행중/완료)
- **사용자가 하는 것**: 휴대폰 본인인증 진행 → 가족관계증명서 업로드(또는 촬영)
- **시스템 피드백**: 업로드 후 "확인 중" → (MVP 자동 승인) 수 초 내 "가족관계 인증 완료"
- **시각적 위계**: 현재 해야 할 항목만 활성, 나머지는 흐리게 → 완료 항목은 체크 아이콘 + 텍스트 "완료"
- **States**:
  - Loading: 업로드 진행률 바 + "제출 중이에요"
  - Error(파일): "이미지는 10MB 이하만 가능합니다" / "JPG 또는 PNG 파일을 올려주세요"
  - Error(네트워크): "제출에 실패했어요. 네트워크를 확인하고 다시 시도해주세요." + `다시 시도`
  - Error(반려, 실심사 도입 후): "제출한 서류에서 가족관계를 확인하지 못했어요. 발급 3개월 이내 서류인지 확인해주세요." + `다시 제출`
  - Success: 초록 체크 + "가족관계 인증 완료" 토스트

### Step 4: 입력 — 부모님 동의 받기

- **사용자가 보는 것**: 동의 방식 선택 — `부모님 휴대폰으로 문자 보내기`(기본) / `부모님과 함께 이 화면에서 동의하기`
- **사용자가 하는 것**: 부모님 성함·연락처 입력 후 문자 발송, 또는 대면 동의 화면에서 부모님 성함 확인 + 동의 버튼
- **시스템 피드백**: 문자 발송 시 "동의 요청을 보냈어요" + 대기 카드(재발송 타이머 3분). 대면 동의 시 성함·동의 시각을 기록하고 즉시 완료
- **시각적 위계**: 기본 방식(문자)을 크게 → 대안(대면)은 아래 보조 버튼 → 하단에 "부모님은 언제든 동의를 철회하실 수 있어요" 고지
- **States**:
  - Loading: 발송 중 버튼 스피너
  - Empty(대기): "부모님의 동의를 기다리고 있어요" + 남은 시간 + `다시 보내기`(3분 후 활성)
  - Error: "문자를 보내지 못했어요. 번호를 다시 확인해주세요." / "이미 다른 계정에 등록된 번호예요."
  - Success: "부모님 동의 완료" 배지 획득

### Step 5: 입력 — 프로필 작성 (섹션 분할 + 자동 임시저장)

- **사용자가 보는 것**: 6개 섹션의 단계형 폼 — ① 기본정보 ② 사진(**최소 3장**, 최대 5장, 대표 1장) ③ 혼인·가족 ④ 종교·생활 ⑤ 관계 목적(최대 2개) ⑥ 취미·소개글·부모님의 한마디·사주(선택). 상단에 진행률.
- **필수 항목**: 성함·성별·생년월일·거주지역·관계 목적·사진 3장·자녀 수·동거 가족·종교·직업·음주·흡연·취미·소개글·만나고 싶은 분. 선택은 **부모님의 한마디**와 사주뿐이다. 값이 비면 상세 화면이 사진과 이름만 남아 상대 자녀가 판단할 근거가 없어진다.
- **고정 보기로 받는 항목**:
  - 동거 가족 — `혼자 거주 / 자녀와 거주 / 형제와 거주 / 부모와 거주` (**복수 선택**)
  - 흡연 — `비흡연 / 흡연` (단일 선택)
  - 자유 입력이면 "혼자삽니다"·"독거"·"혼자 거주"가 전부 다른 값이 되어 표기가 제각각이 된다.
- **동성 친구 안내**: 관계 목적에서 '동성 친구'를 고르면 칩 바로 아래에 *"동성 친구를 선택하시면 같은 성별의 동성 친구를 찾는 분만 추천됩니다."*를 즉시 표시한다 — 추천 결과가 통째로 달라지는 선택이라 나중에 알면 늦다.
- **사용자가 하는 것**: 섹션별 입력, 사진 업로드/대표 지정, 관계 목적 선택
- **시스템 피드백**: 섹션 이동 시 자동 임시저장 + "임시저장됨" 마이크로카피. 관계 목적 3번째 선택 시 버튼 비활성 + 안내
- **시각적 위계**: 섹션 제목 → 필수 항목 → 선택 항목(접힘) → 하단 고정 `다음`
- **States**:
  - Loading: 사진 업로드 썸네일 자리 스켈레톤 + 진행률
  - Empty: 사진이 3장 미만일 때 "사진을 최소 3장 등록해주세요 (현재 N장)" 안내
  - Error(사진): "이미지는 10MB 이하만 가능합니다" / "사진은 최대 5장까지 올릴 수 있어요"
  - Error(관계 목적): "관계 목적은 최대 2개까지 선택할 수 있어요" / "'아직 잘 모르겠어요'는 다른 항목과 함께 선택할 수 없어요"
  - Error(연령): "만 50세 이상만 등록할 수 있어요" (TODO-02)
  - Error(글자수): "소개글을 입력해주세요" / "500자 이내로 작성해주세요"
  - Success: 섹션 완료 시 체크 표시, 마지막 섹션에서 `미리보기로 이동`

### Step 6: 대기/결과 — 부모님 최종 승인 → 검수 → 공개

- **사용자가 보는 것**: 실제 공개될 카드/상세를 그대로 보여주는 미리보기 + "부모님께 이 화면을 보여드리고 승인을 받아주세요" 안내 + `부모님 승인 요청` / 승인 후에는 검수 상태 카드(검수 중 / 공개 중 / 반려)
- **사용자가 하는 것**: 미리보기 확인 → 승인 요청 → 결과 대기
- **시스템 피드백**: 승인 완료 시 검수 대기로 전환. 검수 통과 시 푸시 "프로필 검수가 완료되어 공개되었어요"
- **시각적 위계**: 상태 배지(가장 큼) → 다음에 할 일 한 문장 → 프로필 미리보기 → 보조 액션(`수정하기`, `공개 중단`)
- **States**:
  - Loading: 상태 조회 스켈레톤
  - Empty: 해당 없음
  - Error(반려): "프로필이 반려되었어요 — 사진에 얼굴이 보이지 않습니다. 수정 후 다시 제출해주세요." + `수정하기`
  - Success: "공개 중" 배지 + 인증 배지 4종(자녀 본인인증 / 가족관계 인증 / 부모님 동의 / 검수 완료)

### Step 7: 이탈/철회 — 언제든 되돌릴 수 있다

- **사용자가 보는 것**: 마이페이지의 `프로필 공개 상태` 항목과 `프로필 공개 중단` 버튼
- **사용자가 하는 것**: 공개 중단 토글 또는 부모님의 철회 요청 접수
- **시스템 피드백**: 확인 다이얼로그 → 즉시 비공개, 받은 하트/대화는 유지하되 새 추천에서 제외
- **시각적 위계**: 현재 상태(공개 중/비공개) → 상태를 바꾸는 버튼 → 결과 설명 문구
- **States**:
  - Error: "공개 상태를 변경하지 못했어요. 잠시 후 다시 시도해주세요."
  - Success: "프로필을 비공개로 전환했어요" 토스트 + 상태 배지 변경

## Visual Hierarchy Notes

- 등록 플로우의 모든 화면에서 가장 먼저 보여야 할 것은 **"지금 무엇을 해야 하는가" 한 문장**이다. 진행률은 그다음.
- 상태 카드에서는 **상태 배지 → 다음 행동 → 상세**. 검수 중인데 `수정하기`가 제일 크면 안 된다.
- CTA 레이블은 동작을 그대로 쓴다: `부모님 등록하기`, `동의 문자 보내기`, `부모님 승인 요청`, `프로필 공개 중단`. "확인", "완료" 같은 모호한 레이블 금지.
- 정보 우선순위: 크기(상태 배지) → 대비(다음 행동 CTA) → 위치(상단 고정) → 여백(섹션 구분) → 굵기(라벨).

## Consistency Checklist

- [ ] 인증/동의/검수의 상태 배지가 앱 전체에서 같은 컴포넌트·같은 색 규칙을 쓴다
- [ ] 사진 업로더가 프로필 수정 화면에서도 동일하게 동작한다
- [ ] 파괴적 동작(공개 중단, 탈퇴)은 항상 확인 다이얼로그 + 동일 문구 패턴
- [ ] 폼 에러는 필드 하단 인라인 메시지로 통일 (토스트로 대체하지 않는다)

## Accessibility Notes

- 터치 타겟 최소 44×44px — 사진 삭제 X 버튼, 관계 목적 칩 포함
- 텍스트 대비 4.5:1 이상 — 중장년 자녀도 사용하므로 본문 최소 16sp, 상태 문구 굵게
- 색상만으로 상태를 전달하지 않는다: 배지는 아이콘 + 텍스트 병행("✓ 인증 완료")
- 에러: 빨간 테두리 + 에러 아이콘 + 구체 문구 3종 세트
- 사진 업로드 항목에 accessibilityLabel("대표 사진, 1번째") 부여

## Technical Notes

- **Processing**: Server-side (인증·동의·검수 상태 전이는 서버 권한), 이미지 리사이즈는 클라이언트 선처리 후 업로드
- **Data Flow**: 자녀 인증 입력 → 서버 검증/기록 → 부모님 동의 이벤트 → 프로필 draft 저장 → 승인 → 검수 → `공개` 상태로 전이 → 추천 인덱스에 편입
- **Dependencies**: Supabase(Auth, Postgres, Storage, RLS), 휴대폰 본인인증(MVP는 플로우만), SMS 발송, 이미지 업로드/서명 URL
- **보안**: 가족관계증명서 원문은 별도 비공개 버킷 + 인증 결과 플래그 위주 저장, 다른 사용자에게 절대 노출 금지 (PRD 15장)
