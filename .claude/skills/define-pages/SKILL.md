## Auto Mode

`docs/progress/auto-mode.json` 파일이 존재하고 `enabled=true`이면:
- AskUserQuestion을 사용하지 않는다 — AI가 자율적으로 최적 결정
- 탭 구조 검증 (Phase 2.2): "이대로 진행" 자동 선택
- 페이지 목록 검증 (Phase 3.1): "이대로 진행" 자동 선택
- 네비게이션 질문 (Phase 4): AI가 best practice 기반 자율 결정 (기본 탭=최고 빈도 기능, 상태 유지=yes, cross-feature 연결=공유 데이터 모델 엔티티 기반)
- Completion 후 `/design-wireframes`를 즉시 호출

## Instructions

You are an information architect who transforms multiple UX feature specifications into a unified page/screen inventory with routing structure and navigation hierarchy.

### Phase 1: Read & Analyze

1. Read `docs/features/feature-summary.md` (generated by `/clarify-core-feature`)
2. If `docs/features/data-model.md` exists, read it too
3. Present a consolidated summary:

```
기능 스펙 {count}개 분석 완료:

1. {Feature A} — {User Goal} ({journey step count}개 단계)
2. {Feature B} — {User Goal} ({journey step count}개 단계)
3. {Feature C} — {User Goal} ({journey step count}개 단계)

총 Journey 단계: {total}개
데이터 모델: {있음/없음}
```

NOTE: `feature-summary.md`에 필요한 정보가 모두 포함되어 있으므로, 개별 기능 스펙 파일(`{feature-name}.md`)을 직접 읽지 않는다.

---

### Phase 2: Tab Structure Design

Before listing individual pages, determine the overall tab (bottom navigation) structure.

**Step 2.1: Propose Tab Structure**

Based on all features combined, propose 3-5 bottom tabs:

```
하단 탭 구조 제안:

1. {Tab A} — {어떤 기능의 메인 화면}
2. {Tab B} — {어떤 기능의 메인 화면}
3. {Tab C} — {어떤 기능의 메인 화면}
4. {Tab D} — (공통) 마이페이지/설정
```

Rules:
- 하나의 탭에 여러 기능이 묶일 수 있음
- 가장 자주 사용하는 기능 → 첫 번째 탭
- 공통 화면(마이페이지, 설정)도 포함
- 기능 간 연관성 고려하여 그룹핑

**Step 2.2: Validate Tab Structure**

**Auto mode**: "이대로 진행" 자동 선택. AskUserQuestion 스킵.

**Interactive mode**: Ask using AskUserQuestion:
- Question: "탭 구조가 적절한가요?"
- Options:
  1. "이대로 진행"
  2. "탭 추가/수정 필요"
  3. "탭 삭제 필요"
  4. "탭 그룹핑 변경"
  5. "전체 재구성"

Repeat until "이대로 진행".

---

### Phase 3: Unified Page List

From all features' User Journeys + confirmed tab structure, derive every distinct screen:

| # | Screen Name | Route | Type | Tab/Parent | Source Feature | Description |
|---|------------|-------|------|------------|----------------|-------------|
| 1 | {화면명} | {route} | Tab/Stack/Modal/BottomSheet | {탭 or 부모} | {기능명} | {한 줄 설명} |

**Type definitions:**
- **Tab**: 하단 탭 네비게이션의 루트 화면
- **Stack**: 탭 내에서 push되는 화면 (뒤로가기 가능)
- **Modal**: 전체 화면 모달 (독립적 플로우)
- **BottomSheet**: 하단 시트 (부분 오버레이)

**Routing rules for Expo Router v6:**
- Tab screens: `app/(tabs)/{tab-name}/index.tsx`
- Stack screens: `app/(tabs)/{tab-name}/{screen-name}.tsx`
- Modal screens: `app/{modal-name}.tsx`
- Auth screens: `app/(auth)/{screen-name}.tsx`

**Cross-feature considerations:**
- 여러 기능에서 공유하는 화면은 한 번만 정의 (Source Feature에 모두 표기)
- 기능 간 이동이 필요한 경우 Navigation에 명시
- WebView 페이지가 필요한 경우 별도 식별: `apps/webview/src/pages/{path}/`

**Step 3.1: Validate Page List**

**Auto mode**: "이대로 진행" 자동 선택. AskUserQuestion 스킵.

**Interactive mode**: Ask using AskUserQuestion:
- Question: "전체 페이지 목록이 적절한가요?"
- Options:
  1. "이대로 진행"
  2. "페이지 추가/수정 필요"
  3. "페이지 삭제 필요"
  4. "전체 재구성"

Repeat until "이대로 진행".

---

### Phase 3.5: UX/UI Designer Review

탭 구조와 페이지 목록이 확정된 후, UX/UI 디자이너 에이전트를 spawn하여 리뷰를 받는다.

1. `ux-ui-designer` 에이전트를 **단발로** spawn한다 (`.claude/agents/ux-ui-designer.md`) — 리뷰 본문이 에이전트의 반환값이다
   - `Agent(subagent_type: "ux-ui-designer", run_in_background: true, description: "UX review: page-structure", prompt: …)`
   - 프롬프트에 다음을 **인라인으로** 넣는다 (파일을 다시 읽게 하지 않는다):
     - 리뷰 모드: `page-structure`
     - 확정된 탭 구조 전문
     - 전체 페이지 목록 전문
     - 제품 유형·타겟 사용자 한 줄 (feature-summary.md 에서 발췌 — 경로 대신 발췌문)
   - 와이어프레임·데이터모델·앱 코드는 읽지 말라고 명시한다 (토큰 예산: 리뷰 1건 툴 호출 ≤12)
2. 대기 중 Phase 4 의 독립 작업을 진행하고, 완료 알림으로 리뷰 결과를 받는다
3. 피드백 반영:
   - 평가 A → 그대로 진행
   - 평가 B/C → 개선 제안을 반영하여 탭 구조/페이지 목록 수정

**리뷰어 대기에는 상한을 둔다 (auto mode 필수).** 리뷰는 품질 향상 수단이지 phase 의 전제가 아니다.
응답하지 않는 리뷰어를 무한정 기다리면 이 phase 가 정체되고, 라우터의 정체 감지가 파이프라인을
통째로 중단시킨다. 대기 중에는 리뷰와 무관한 독립 작업을 먼저 끝내고, `ListAgents` 로 생존을 확인한 뒤,
그래도 응답이 없으면 `mobile-ux-ui-design` 체크리스트로 **셀프 리뷰를 대신 수행하고 진행한다**
(`detail.ux_review` 에 `"self (reviewer unresponsive)"` 로 남긴다).
**리뷰어 미응답을 `phase_blocked` 사유로 쓰지 않는다** — 산출물은 이미 만들어졌다.

**Auto mode**: 에이전트의 개선 제안을 자동으로 반영한다. AskUserQuestion 스킵.
**Interactive mode**: 에이전트의 피드백을 사용자에게 보여주고 반영 여부를 확인한다.

---

### Phase 4: Clarify Navigation & Details

**Auto mode**: AI가 best practice 기반으로 자율 결정. AskUserQuestion 스킵.

**Interactive mode**: Ask targeted questions using AskUserQuestion, ONE at a time.

**Tab-level questions:**
- 앱 시작 시 기본 탭은?
- 탭 간 이동 시 상태 유지 여부?

**Cross-feature navigation:**
- {Feature A} 화면에서 {Feature B} 화면으로 직접 이동이 필요한 곳은?
- 기능 간 공유 데이터가 있는 화면의 진입점은?

**Per-page questions (ambiguous pages only):**
- 이 화면의 핵심 역할 1가지는?
- 데이터를 서버에서 가져오나요, 로컬인가요?
- 뒤로가기 시 어디로 돌아가나요?

**Shared screens:**
- 기존 보일러플레이트 화면(로그인, 프로필 등)을 재사용하나요?

Rules:
- After every 3-4 questions, give a progress summary
- Total questions: 8-15 depending on page count
- Skip questions for pages that are clearly defined in the feature spec
- When a page's purpose is obvious from the journey step, confirm rather than ask open-ended

### Interaction Rules

1. Ask ONE question at a time.
2. Skip questions for pages that are clearly defined in the feature spec.
3. When a page's purpose is obvious from the journey step, confirm rather than ask open-ended.
4. Always identify reusable existing screens from the boilerplate before creating new ones.
5. Keep route naming consistent with Expo Router v6 conventions.
6. Consider cross-feature navigation — pages from different features may link to each other.
7. Group pages by tab in the final output for clear hierarchy.
