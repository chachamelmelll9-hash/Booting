# Question Guide by Journey Step Type

## 발견(Discovery)
- 사용자가 이 기능을 처음 어떻게 알게 되나요? (온보딩 튜토리얼, 탭 아이콘, 컨텍스트 추천, 푸시 알림 등)
- 기능의 가치를 한눈에 이해할 수 있나요? (아이콘+레이블, 설명 문구, 빈 상태 안내 등)

## 진입(Entry)
- 앱 어디에서 이 기능에 접근하나요? (탭, 버튼, 메뉴, 자동 트리거 등)
- 진입 시 사용자가 즉시 이해할 수 있는 화면 제목/안내가 있나요?

## 입력/선택(Input)
- 주요 입력 방식은 무엇인가요? (카메라, 갤러리, 파일, 텍스트, 음성 등)
- 단일 입력 vs 다중 입력?
- 입력 제약 조건이 있나요? (형식, 크기, 개수)
- 잘못된 입력 시 사용자에게 어떤 구체적 메시지를 보여줄까요? ("잘못된 입력"이 아니라 "이미지는 10MB 이하만 가능합니다" 같은 구체적 안내)

## 대기/진행(Waiting)
- 예상 처리 시간은? (즉시/1-3초/3초 이상/수 분)
- 진행 표시 방식은? (없음/스피너/스켈레톤/프로그레스 바+설명 문구)
- 사용자가 대기 중 다른 작업을 할 수 있나요? (블로킹 vs 백그라운드 처리)

## 결과 확인(Result)
- 결과를 어떻게 표시하나요? (리스트, 그리드, 상세 뷰, 오버레이 등)
- 가장 중요한 정보 1가지는 무엇이며, 가장 크고 눈에 띄게 표시되나요? (시각적 위계 원칙 적용)
- 결과가 없을 때(Empty State) 어떻게 안내하나요? (일러스트+설명+CTA 버튼)
- 결과에서 사용자가 할 수 있는 인터랙션은? (편집, 삭제, 공유, 저장)

## 후속 행동(Next Action)
- 결과 화면의 주요 CTA 버튼은 무엇인가요? (동작을 명확히 설명하는 2-3단어: "변경사항 저장", "장바구니 담기" 등)
- 다시 시도/재실행이 가능한가요?
- 결과를 저장하거나 히스토리로 관리하나요?

## 이탈/완료(Exit)
- 완료 시 피드백은 무엇인가요? (토스트 메시지, 성공 화면, 자동 이동)
- 중도 이탈 시 데이터를 보존하나요? (임시 저장, 경고 다이얼로그)
